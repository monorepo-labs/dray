# The browser

**Chromium embedded through CEF (cef-rs), behind the `cef` cargo feature, macOS only.** [cef.rs](../src-tauri/src/cef/cef.rs) owns the tabs; [automation.rs](../src-tauri/src/cef/automation.rs) is `dray browser`. Design and the rejected routes (screencast, WKWebView) are in DRA-155. Dev: `pnpm tauri dev --features cef` with `CEF_PATH` pointing at the framework, after `scripts/cef-dev-bundle.sh` has laid the helpers beside the debug binary — nothing runs it for you, and a cleaned `target/` takes it away. **A dev build's profile root is `browser/` in its own home**, the same split the socket makes: Chromium holds a singleton lock on the root, so a dev build sharing the release app's — or another worktree's — failed to initialize and *exited the process* (DRA-172). **The downloaded framework splits the same way, `~/.dray/cef-dev`**: the download sweeps every version but its own, so a dev build on a newer CEF deleted the framework the running release app's helpers load from.

**The bundle ships the five helper apps and never the framework.** Chromium is ~330MB unpacked, and in the bundle it would ride every download and every update. [chromium.rs](../src-tauri/src/chromium.rs) fetches it a few seconds after the window first opens — no prompt, no opt-out — from Spotify's CDN (`cef-builds.spotifycdn.com`, the minimal tarball, arch by `consts::ARCH`), pinned to the `cef` crate's CEF version with size and sha256 of each tarball beside it. Same shape as the transcription models: tarball to `.part`, size and hash checked, only `Release/<framework>` unpacked by `/usr/bin/tar` into `<version>.part/`, renamed to `~/.dray/cef/<version>/`, everything else in that directory swept. Progress is a `chromium_status` event every 4MB; the settings row (Integrations) and the Browser tab's empty state draw `describeChromium`'s one sentence. Failure backs off through four retries and Retry wakes the wait rather than starting a second loop.

- **`paths()` finds the helpers in the bundle and the framework wherever it is** — beside them only in the dev layout, else the download. `create_tab` checks `paths()` *before* `ensure_started`, since that one remembers a failure for the life of the process: a tab asked for mid-download must answer "Chromium is still downloading (n%)", not write CEF off. `dray browser` gets the same sentence through `browser_open`.
- **The helper reads `--framework-dir-path` off its own argv.** CEF forwards the browser's `framework_dir_path` to every child under that switch, and the bundle-relative `../../..` the wrapper's loader assumes does not hold once the framework lives in `~/.dray`.
- **Signing is two halves and the bundler does one.** Tauri signs the app with no `--deep` and signs nothing `bundle.macOS.files` copied, and codesign refuses an app whose nested bundles carry no signature — so [cef-helpers.sh](../scripts/cef-helpers.sh) signs the helpers first, with their own [HelperEntitlements.plist](../src-tauri/HelperEntitlements.plist) (library validation off for the ad-hoc-signed framework, JIT for V8), and the app's [Entitlements.plist](../src-tauri/Entitlements.plist) carries library validation off too. [tauri.cef.conf.json](../src-tauri/tauri.cef.conf.json) is the overlay putting them in `Contents/Frameworks` and running that script as `beforeBundleCommand`; release.yml verifies both entitlements and the framework's *absence* after the build. Compiling the bindings needs the CEF SDK in `CEF_PATH` plus cmake and ninja, and nothing copies its framework out.
- **The hook builds nothing, and that is what keeps a release at one compile.** `tauri build --bins` already compiles `dray-helper` per target, with `MACOSX_DEPLOYMENT_TARGET` set from `minimumSystemVersion` and `custom-protocol` on — and every crate `cc` compiles fingerprints that variable, so a cargo build under any other env reruns those build scripts and rebuilds the tree above them, twice over once the CLI's build follows. That was 28 of a 31-minute release, with the cache restored and unusable.
- **To try the download route under dev**, remove the framework symlink `cef-dev-bundle.sh` leaves in `target/debug/cef/Dray.app/Contents/Frameworks`; the helpers stay and the app fetches its own. **To try a signed bundle**, `pnpm tauri build --debug --features cef --bundles app --config src-tauri/tauri.cef.conf.json` — ad-hoc, but the hardened runtime and both entitlement files are real. **That bundle is not a dev build to the socket**: `is_dev()` is `tauri dev` alone, so it binds `~/.dray/dray.sock` and takes the channel from the release app until that is relaunched. Quit the release app first, or test through `dray.sock` and relaunch it after.

**Each session has its own tabs and its own profile** — `RequestContext` with `cache_path` a *direct child* of `root_cache_path` (`~/.dray/browser/<session-id>`), or CEF refuses the profile. The native view sits above the webview, so nothing in the DOM can draw over it: modals hide it (a body `pointer-events: none` observer) **only where something open lands on it** (`judgeOcclusion`: popper wrappers and dialog overlays measured against the view's rect, two frames on so the popper is placed) and **behind a JPEG of the page** captured first and drawn in its place (`browser_snapshot`, `useBrowserSnapshot`) — Radix sets that style for every menu too, a bare hide left the pane a hole for as long as any dropdown was open, and the swap to a 1x picture is visible on its own, so a menu opened elsewhere touches nothing; tooltips open `side="top"`, and a "new tab" is *pending* with no browser behind it so the pane can draw an empty state.

- **Settle and delete remove the profile** (`delete_profile` in [automation.rs](../src-tauri/src/browser/automation.rs), from `SessionManager::settle`, for CEF's root and headless's both). Cookies go with it, so an unsettled session's browser starts signed out. **Renamed first, removed on a thread** (`discard`): a profile is hundreds of megabytes, and the rename means a profile the session makes again a moment later is a new directory that nothing is deleting. **The app removes it a second time** (`purge_later`, 5s after the session's last browser closes), because Chromium writes into the profile as its tabs close. Measured: `Preferences`, `Cache` and the network state came back at the old path, carrying the old site settings.
- **The launch sweep is temporary** (`sweep_browser_profiles` in [serve.rs](../src-tauri/src/serve.rs), #482). It clears the backlog from before settle removed profiles, judged against the index: any uuid-named profile whose session is gone or settled. Delete it in a later release, once no build that settles without cleaning up is still around. It is awaited before the server listens, so a session made meanwhile cannot lose a profile it just opened; only the renames are waited on. It sweeps nothing on an empty index, and skips CEF's root under `DRAY_HOME`, since that root ignores the variable and another home's index would read every profile there as orphaned.
- **History is Dray's own record, per session, in the profile** (`dray-history.json`, [history.rs](../src-tauri/src/cef/history.rs)), so it goes when the profile goes. Chromium keeps its own in `History`, but that is SQLite under an exclusive lock while the profile is open, so reading it would cost a new dependency and a copy per read. A visit is a main-frame commit of an `http(s)` URL, from `on_address_change`, with title and icon filled in by the handlers after it. Those handlers run on the main thread, so they only mark the list, and a `browser-history` thread writes it at most once a second. A closing tab records nothing, or a late callback would load a forgotten session's list back, and `browser_history` reads from disk without caching for the same reason. The empty state lists the newest eight, and the URL bar suggests matches as you type (`matchHistory` in [history.ts](../src/lib/history.ts)). **The suggestion list hides the page through `setSuggesting`, not through the occlusion judge**, which only runs under Radix's modal lock — and a lock would stop the field taking keys.
- **The panel's Browser tab is always drawn**, page or not. Its empty state is a URL bar, the recent pages and the local servers, which is a place to start rather than a sentence saying there is nothing.

- **The message pump sleeps while no browser is alive** (`start_pump`). CEF's own requests drive it; the 33ms safety net cefclient runs forever only runs while a browser exists or is being created (`CREATING`, counted from the create to `on_after_created`, since a create under load has no time bound). The net is not optional during creation — measured: without it not one tab opened — and an immediate request must run before a later delayed one can replace it, or the same stall comes back.
- **Chromium's init resets SIGCHLD to `SIG_DFL`, and `execute_process` and `initialize` both run inside `keeping_signal` for it.** That reset wipes the handler tokio reaps children through, so every later `git` spawn waited forever — and `send_msg` awaits one under the sessions lock, which made one tab opened leave every session unsendable and unstoppable until restart (DRA-166). Diagnosed by a `<defunct>` `git` under the app in `ps`; that is the shape to look for if a child wait ever hangs again.
- **Never hold the `TABS` lock across a call into CEF.** `load_url` fires `on_loading_state_change` before it returns, and that handler takes the lock. Clone the `Browser` out (`browser_of`), drop the guard, then call.
- **`do_close` returns 1 and removes the `NSView` itself.** CEF's default sends `performClose:` to the top-level window, which is Dray's quit prompt, and returning 1 alone destroys nothing.
- **A hidden `NSView` drops input.** Chromium marks the widget hidden and every mouse and key event dispatched to it goes nowhere, measured with a page listener. `reveal` unhides the view off-screen for an input verb and `apply_layout` puts it back. Screenshots and `eval` work hidden; only input needs this. **The same drop takes the app's own chords when the view is hidden with focus still inside it** — hiding does not resign first responder, so ⌘E closed the panel and nothing reopened it until a click. `apply_layout` hands focus back to the `WKWebView` before hiding a view that holds it.
- `Target.createTarget` over the debug port is refused by CEF, so tabs are created through `browser_host_create_browser` only.
- **A popup is CEF's, not a tab made beside it.** `on_before_popup` rewrites the window info and client to ours and returns 0, so `window.open` answers a real window that OAuth flows post back through; cancelling and opening the URL as a fresh tab returned `null` to the page.
- **A tab's id is Dray's, minted in `NEXT_TAB` and carried on its `DrayClient`, never `browser.identifier()`.** Every handler reads `self.tab`, and the DevTools observer does too. That is what lets a discarded tab come back as the same tab to the strip and to `dray browser tab <id>`. `on_before_close` still removes only the browser instance it holds (`is_same`, called with the lock released).
- **A tab nobody has seen for 30 minutes is discarded** (`sweep`, #424). The renderer goes and the entry stays, with its URL, title and favicon. CEF has no discard of its own: Chrome's lives above the layer CEF exposes, so a discard is `close_browser` with `discarded` set first, and `on_before_close` reads that flag to keep the entry. **Seen means drawn**: the presented session's active tab while the pane is visible (`shown_tab`). A closed panel or another view counts as unseen, and so do the other tabs in the strip. Any `dray browser` verb counts as seen too. The tab on screen is woken in `apply_layout`; a verb on the active tab is woken in `run` (`awake`); `tab` lists a ghost without waking it. A tab is never discarded while it is loading, recording, picking, driven, mid-shot, or either half of a live popup pair. Measured cause: one renderer on a page failing against a dead server reached 5.7GB in 20h. History and page state are lost, as in Chrome; cookies are not, since the profile is on disk.
- **The picker's console channel is gated per tab and typed.** Any page can log the prefix; only a tab whose picker this app started is listened to, once, and only a payload shaped like `PickedElement`. A render-process binding would be the trusted channel.

**`dray browser` is agent-browser's grammar on Dray's own tabs — no agent-browser binary, no MCP, no debug port.** Each browser gets a DevTools channel of its own (`send_dev_tools_message` in, a `DevToolsMessageObserver` out), so an action is a few CDP calls on the agent's tab and the session id is the only address: an agent can reach no other session's pages by construction. Pointer and key verbs use `Input.dispatch*`, since that is what a person's click does; locators and reads are one page-side script, `HELPERS_JS`, shared by `snapshot` and `find` so the two name the same element.

- **The agent's tab is its own, never the reader's active tab** (`DRIVEN` in [automation.rs](../src-tauri/src/browser/automation.rs), #738). It is the tab the agent last opened or switched to; the reader clicking or duplicating a tab moves only what is on screen. Shared, a reader who duplicated the agent's dev-server tab to use it had the agent's next verb land in their copy. **Closed under it, the agent takes a tab on the same origin, else a new tab at its last URL** — never a tab on another site, which is the reader's. Before it has driven any, the reader's active tab is the one handed over; `open` with no tab of its own opens a new one rather than navigate the reader's away. Closed by the agent itself, the next verb asks for `open`. `tab`'s `*` marks the agent's tab. In memory only, so a restart hands the active tab over again.
- **Protocol v5.** `Request::Browser` fails to parse on an older app, which reads as a broken CLI rather than an app with no browser; the bump makes it "update the Dray app". **Do not install a v5 `dray` over `~/.local/bin` while the release app is what reviewers run on** — every `dray send` there is refused. Test through the dev socket: a wrapper setting `DRAY_ENDPOINT=~/.dray/dray-dev.sock` in front of `apps/cli/target/debug/dray`.
- **`wait_loaded` watches for loading to *begin* before waiting for it to end.** A click's CDP reply lands before the renderer has left the page, so "not loading" answered at once is the old page, and the next verb reads the old URL. 600ms window, then assume no navigation.
- **`scroll` is `window.scrollBy`, not `mouseWheel`.** The wheel event never answers on a page with nothing to scroll, and hangs the verb for the full timeout.
- **`press Enter` carries `unmodifiedText` beside `text`.** With `text` alone the key types and does not submit a form.
- **A shot hides the view and draws the page's own still in its place, with nothing on top of it** (`browser_shooting` → `shooting` in [browser.ts](../src/lib/browser.ts), `Snapshot` in [BrowserPane](../src/components/browser/BrowserPane.tsx)). The capture lays the page out at the asked-for size and the widget doing that is the one the reader is watching, so a screenshot was a visible reflow and a snap back. It rides the **same hide and the same still** a modal uses, one more reason in `present()` rather than a second path, and only for the session being photographed. **The shutter opens before the override lands**, so what is photographed is the page as the reader last saw it and the swap is invisible. **A scrim and a camera sat on that still for a while and were deleted**: the still is the page pixel for pixel, so the freeze cannot be seen and anything drawn over it is a flash where there was none — which read as the very flicker the cover exists to remove. A screenshot is not an event the reader must be told about; they asked for it. **`SETTLE` is spent at all three edges** — after the hide, after the override goes on, after it comes off — each one a frame where the wrong thing would otherwise be on screen. And **the ack is queued on the main thread**, which is the whole of it being true: `browser_layout` hands `apply_layout` to `run_on_main_thread` and returns at once, so the pane's "the hide landed" was really "the hide was asked for" — it acked, the override went on, and the reader watched the page reflow in a view still on screen. `hiding()` is one predicate because the still, the paint callback and the layout call must agree: asked separately, a shot drew a still nothing would hide behind.
- **`browser_snapshot` is let past `CAPTURING` while the shutter is open, and that exception is what makes the cover the page rather than a blank.** The lock is held for the whole shot, so the cover asked for *inside* one would be refused — and the cover is the thing the shot hides behind. Safe exactly there: `SHUTTER_OPEN` is true only between the shutter opening and the override going on, which is the window where the page still reads the way the reader sees it. Closed before `capture`, never after, or the cover would be a picture of the very reflow being hidden.
- **The shot waits for the pane to say it is covered, and never guesses.** `browser_shutter_ready` → `SHUTTER_READY`. **An ack names the shot it is for, and a bare `Notify` was not enough**: one shot is answered twice where the pane has nothing to cover — once outright, once when the hide it asked for lands — so the spare notification sat as a stored permit and released the *next* shot before its own still was painted, putting the reflow back on screen every other capture (caught in review on #204). `SHUTTER_ACK` carries how far the pane has got and the `Notify` only wakes the waiter to look, so a late ack is a number too small to release anything; the frontend captures the number where the answer is *promised*, not where it arrives. **A pane with nothing of that session on screen answers at once**, or every screenshot taken with the browser tab shut would sit out the whole timeout for a cover it never needed. `SHUTTER` is the cap alone (700ms), and reaching it shoots anyway — which is exactly what the verb did before it covered anything. The shutter closes on the failing path too, beside the metrics override, or a timed-out capture leaves the page frozen for good.
- **`set device` names live in `DEVICES` and in `VIEWPORT_PRESETS` both**; a test holds them together. **The agent's size is capture-only and never reaches the pane** — `Emulation.setDeviceMetricsOverride` lays the page out for the capture alone, and the widget keeps the pane's size. It used to ride a `browser_viewport` event into the pane's own store so the device bar could show what the agent set; that store is what puts the stage into device-preview layout, so one sized screenshot left the reader's page centred and padded inside the pane for the rest of the session, with the bar that explains it closed by default and nothing clearing it (DRA-233). The bar is the reader's alone, and their pick still letterboxes, that being what they asked for.
- `console`/`errors` drain a per-tab buffer fed from `on_console_message`; the picker's own lines are kept out of it.

**`dray browser record start` / `record stop [name]` films the active tab to an MP4, so the reader verifies by watching** ([recording.rs](../src-tauri/src/recording.rs), `RECORDING` in [automation.rs](../src-tauri/src/cef/automation.rs)). No new crate and no ffmpeg:

- **Frames are `Page.captureScreenshot` JPEGs asked for on a 33ms clock (`film`), muxed by hand into a Photo-JPEG `.mov`**, then `/usr/bin/avconvert` turns that into H.264. **Not `Page.startScreencast`**: this CEF build sends a screencast frame only when scroll offset or size changes, so typing, hover and animation never reached the video (measured: one frame in 4s with rAF at 62/s). A capture forces a fresh frame; captures run back to back, so 2x lands near 20fps, not 30. A frame identical to the last is dropped and gaps are capped at 1s in `stts`, so an agent thinking for a minute costs a second of video — unless a caret is blinking. **Apple's decoder wants 4:2:0 JPEGs**; a 4:4:4 frame answers "Cannot Decode".
- **Always filmed at 2x device pixels** (`RECORD_SCALE`), with no flag: 1x blurs text, and avconvert's preset holds the bitrate at ~1.8Mbps whatever the resolution, so 2x cost 5% more file in the test. Layout stays at the viewport's CSS size, so an iPhone SE recording is a phone at 750×1334, not a tablet.
- **The recorded view is parked off-screen at the recording size, never hidden** (`parked`, `apply_layout`): a hidden `NSView` runs no `requestAnimationFrame`, so a page animated from script films frozen. A covered Dray window still throttles rAF to ~12/s despite `disable-backgrounding-occluded-windows`, so script animation films choppier behind another window.
- **`type` and `fill` key text in a character at a time while the tab is recorded** (`TYPE_BUDGET`, ≤70ms a character, 4s at most), since one `Input.insertText` films as a paste. Unrecorded, it stays one call. **The page blurs between verbs**: `apply_layout` takes first responder off the parked view, or the reader's own keystrokes would land in the recorded page — so a focus ring drops out for the gap between two verbs.
- **One recording per session, any number across sessions**, keyed by session. Screenshots still work mid-recording: the recorded tab is paused for the shot rather than refused.
- **The pane holds the shutter for the whole recording and draws `RecordingNotice` over the still**, since the page is laid out at the recording's size, not the pane's. The reader cannot change tabs meanwhile — that once kept the agent's next verb on the recorded tab, and the agent holds its own tab now, so the lock is a candidate to go. The agent's own tab verbs stay open, since a flow may cross tabs.
- Files land in `~/.dray/browser{,-dev}/recordings/<session>/`, deleted with the session, and the asset scope covers them. A recording path in the agent's reply renders as an inline `VideoPlayer`.

**A link in the transcript opens in Dray's browser, flipping the main column to the Browser view rather than opening the side panel; ⌘-click leaves for the system one.** Both the assistant's markdown links and a URL in the user's own bubble go through `openLink`. [LinkDialog](../src/components/chat/LinkDialog.tsx) — the question it used to ask first — stays mounted with nothing raising it; `askLink` is its way back in. URLs in user text are a `url` segment from `highlightSegments`, `http(s)://` only, with the sentence's trailing punctuation left outside.
