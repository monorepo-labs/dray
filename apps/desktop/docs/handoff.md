# Handing work back

**The composer hides a row of canned prompts behind itself.** [HandoffRow](../src/components/composer/HandoffRow.tsx) sits above the composer card, clipped to a sliver, open on hover: Commit, Create PR, Run server as shipped.

**The row is the reader's, one global set, in Settings → Composer** ([HandoffSettings](../src/components/settings/HandoffSettings.tsx)). **The three built-ins are switches, never text fields**: each is shown by a rule about the checkout, and the rule is only right for the words it was written for — a Commit re-prompted into something else would still hide on a clean tree. So the reader switches one off and writes their own words as a button of their own: label, prompt and remove per custom button, plus Add button. The tab opens on a picture of the composer with its row risen and a cursor on it, the Island tab's bargain — "the composer's top edge" says little until seen — drawn from the reader's own config so a switch, a new button or a move shows there at once. **Built-ins and custom buttons are one list, dragged into the row's order** — the Spaces tab's drag, grip and row styling, shared through [rowReorder.tsx](../src/components/settings/rowReorder.tsx), arrow keys on the grip included; `useDragReorder` ignores a press in a textarea as it does in an input, or the prompt field could not be clicked into. Each custom button carries real field labels, since a placeholder is gone once something is typed; its bin shows on hover or focus only, sits after the prompt in the DOM so Tab goes label → prompt, and asks in place (`ConfirmOrKeep`) before removing. Stored in local storage (`ade.handoff`, [useHandoffConfig](../src/hooks/useHandoffConfig.ts)) as one ordered list of `builtin` entries with an `on` flag and `custom` entries, a module store since Settings writes while the composer reads; Rust never reads it. A built-in the stored list lacks is appended switched on, so one a later build adds reaches every reader. A custom button takes Run server's rule, a session and nothing else. One with an empty prompt is never drawn, and an empty label falls back to the prompt's first three words. `readHandoffConfig` reads anything not of the config's shape as the defaults and drops a bad entry alone, so a malformed value never breaks the row. **More buttons than fit scroll sideways rather than wrap**: the zone is `w-fit` capped at the card's width, or the row would draw over the panel beside it, and each button is capped at `max-w-48` with its label truncated but never shrunk — squeezed to fit, every label went to one letter. No scrollbar, the open window being 32px tall; a trackpad or Tab reaches the rest. The prompt field is a growing textarea, since an `<input>` strips a pasted prompt's line breaks. Analytics: built-ins report `handoff_<id>`, every custom one a fixed `handoff_custom` — label and prompt never leave the machine. [handoff-buttons.html](../demo/handoff-buttons.html) mounts the tab beside the row at both composer widths.

**Every button sends a prompt** through `handleSendMsg`, so there is no confirm dialog and no error surface — whatever goes wrong reports in the transcript like any other tool failure. The agent is not deterministic, so every button is a **suggestion, not a command**.

**The shipped prompts are a few words** — `"commit your changes"`, `"create a PR"`; a reader's own can be any length. A longer default is a spec competing with the repo's own instructions. Pinned by test (≤5 words). **`RUN_SERVER_PROMPT` is the one exception** ([handoff.ts](../src/lib/handoff.ts)): `"start the dev server in the background"`, where **"in the background" is load-bearing** — a bare "run server" makes the CLI run `pnpm dev` in a *foreground* Bash, which blocks until that tool's timeout and takes the server down with it. The length test skips it by id and pins that clause instead, not dodged by leaving `hasSession` default.

**Hidden, not contextually visible, and that is the whole shape.** A turn touching files is most turns, so a row drawn on "there are changes" is a row drawn always. Hiding is also what lets Run server be offered unconditionally, since nothing tracks whether a server is up.

**Which buttons exist is [handoff.ts](../src/lib/handoff.ts), pure and tested.** Dirty tree → Commit. Create PR is hidden on the default branch, where no remote resolves one, where the branch already has a PR (from `usePrMarks.prFor`, not a fourth git call), and where it holds nothing new. That last check reads `ahead_of_base`, **not** `ahead`: `ahead` counts against *upstream*, so a fully pushed branch reads zero — the exact state a branch is in when its PR gets opened. `ahead_of_base` counts `origin/<default>..HEAD`, since a local `main` can be stale or absent in a worktree. `None` means "couldn't tell" and counts as something, since over-offering costs one click where under-offering removes the action.

**One backend command, not three stitched.** `work_status` = `dirty`, `branch`, `upstream`, `ahead`, `default_branch`, `ahead_of_base`, so the row can't draw one button from one snapshot beside another from a different one. `default_branch` arrives **stripped of remote**. Infallible: a non-repo answers defaults. **Read on the falling edge of a turn, on arriving at a session, and on Claude Code's mid-turn `repo_changed`, nothing else** — polling for an editor in another window is several `git` spawns a second to catch something rare.
