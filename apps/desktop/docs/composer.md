# Composer

- **`isNewTask` is the composer's two presentations, not one flag per effect.** Before a session exists the composer stands alone mid-window, so [ChatInput](../src/components/ChatInput.tsx) drops the card's fill, border and padding, moves the toolbar above the input, swaps the placeholder, and replaces the send button with a "Press ⏎ to send" hint. Dropping the button is only safe because Enter-to-send lives in `onKeyDown` rather than in that button being the form's submitter — make it the submitter again and the empty state loses its send path.
- **The error slot reports the reader's own last action failing, and nothing else.** It is one `useState` for the whole app, so anything written there follows the reader to every other session and to the new-task composer. An agent `error` payload therefore is **not** mirrored into it: that error belongs to one session, is persisted, and `EventRow` already draws it as a red row in that session's transcript — mirroring it drew it twice and outlived the conversation it was about. One decision across every harness, not a patch per caller. What remains are `invoke` rejections, which the reader caused a moment ago, so both intentional selection moves (`handleNewSession`, `handleSelectSessionIndexItem`) clear the slot **on the way in** — never on the way out, since the session-not-found rollback writes its own sentence after moving the selection. **Clearing is half of it; `navGen` is the other half.** A send, an interrupt or a permission reply rejects seconds after the reader has moved on, and an unguarded catch writes the previous session's failure into the composer they moved to. So every **session-scoped** catch reports through `failUnlessLeft()`, taken at the start of the action: it captures the navigation generation and writes the slot only while no move has bumped it since. Four moves bump it — select, new task, a send minting a session, a fork opening selected — and the two that also start an action (select's read, send itself) take their `fail` *after* the bump, so their own failure still reports. **App-wide loads and actions stay on the raw setter** — the index, projects, branches, a checkout, a space retag: their failure is as true after a move as before it, and guarding them left a list stale or empty with nothing saying why.
- **A draft belongs to the session, not the composer.** [useDraft](../src/hooks/useDraft.ts) keys unsent text by session id, `null` for a new task. The store is **module-level, and a ref would not do**: `AppShell` renders the footer at a different position when `centered`, so moving between the empty state and a session unmounts `ChatInput` and mounts a fresh one — losing the draft on exactly the switch most likely to be made. Nothing is persisted. [useAttachments](../src/hooks/useAttachments.ts) is the same shape, and also because the `+` button lives in `ComposerToolbar`, which reaches `ChatInput` as an opaque `ReactNode`.

**Slash commands are prompts, not protocol.** Every one travels as ordinary prompt text and the CLI expands it, so sending one needed no new code and nothing new arrives on the wire. Two things follow: the transcript cannot tell a command from prose (the CLI never echoes the prompt back), so [UserMessage](../src/components/chat/UserMessage.tsx) re-parses the text with `parseSlashCommand` to draw the name as a chip; and the command *list* is the only part that needed a backend.

**The command list comes from the `initialize` control request, not from `init`.** `system/init`'s `slash_commands` arrives only once a turn is under way, so it cannot populate a picker for a composer with no session, and it carries bare names where the picker wants a description and argument hint. [commands.rs](../src-tauri/src/harness/claude_code/commands.rs) instead spawns a throwaway child, writes one `initialize` request, reads the reply and kills it: ~1.5s, no model call. Walking `~/.claude/commands` was the rejected alternative, since the CLI merges user, project, plugin and skill scopes and namespaces the results. Results are cached per directory on **both** sides and neither cache invalidates, so a plugin installed while the app is open needs a restart.

**Command source is inferred, and one half of it reads display text.** `commandSource` splits harness / plugin / user from the only two signals the payload carries: a plugin namespaces its name (`railway:deploy`), and a user- or project-scoped command has its scope appended to its *description* (`… (user)`). There is no scope field, so `harness` means "neither of those" and files the CLI's built-ins together with skills Anthropic ships beside them.

**fx's commands are its skills, and they are read off disk because nothing on the wire answers** ([harness/fx/commands.rs](../src-tauri/src/harness/fx/commands.rs)). Same reading Codex's picker takes — the rest of fx's own `/` menu (`/model`, `/clear`, `/login`, `/settings`) is TUI actions Dray already owns in its chrome. What is different is where the list comes from: `available_commands_update` is `[]` at `session/new`, still `[]` after a full turn, and still `[]` in a workspace holding a skill (fx 0.0.10), there is no `skills/list` to ask, no `fx skills` subcommand, and a promptless `session/new` is **persisted** — so an ACP probe would litter `~/.fx/sessions` and answer nothing anyway. So the roots are walked. `WORKSPACE_ROOTS`/`GLOBAL_ROOTS` are fx's own list verbatim, lifted from its `/skills` usage text, including the two asymmetries between the halves (`skills/` and `.opencode/skills` on the workspace side, `.config/opencode/skills` on the global one). First name wins, workspace before global, alphabetical within a root — `read_dir`'s order is stable nowhere and the picker draws what it is handed. Uncached, unlike every other harness's list: those pay seconds for a child where this is a dozen `read_dir`s, and a cache would buy milliseconds at the price Claude Code's and Codex's already pay, which is a skill installed while Dray is open needing a restart.

**The send path needs nothing, and that is the difference from Codex.** fx expands a leading `/name` itself — `/hello then also print DONE-8899` sent as ordinary prompt text ran the workspace's `hello` skill *and* honoured the words after it, verified live — so a pick travels as text the way Claude Code's does and there is no companion to `turn_input` here. **Over-listing is therefore the unsafe direction**: a row fx did not load sends `/name` to a model with no such skill. Hence a skill is a directory holding a *readable* `SKILL.md`, under a name that could be typed after a slash, and **`authorized` where it is a link** — fx refuses one it cannot resolve "to an authorized readable directory" and the two halves fail separately. Captured both ways: a skill linked to `/tmp/elsewhere` was absent from fx's catalog and the model went hunting with `glob_files` for the name it had been handed, where the same skill linked *inside* the workspace ran straight away. So the authorities are the workspace and home, canonicalized — `/tmp` resolves to `/private/tmp` and a plain `starts_with` on the written path finds nothing, the same trap the worktree lock lookup documents. A plain directory is never asked the question at all, or every skill under a symlinked home would drop out. `FX_SKILL_SYMLINK_AUTHORITIES` can add roots and is deliberately unread: its separator is documented nowhere, and a misread one costs a row rather than inventing a dead one. **Block scalars are read** (`description: >` with the sentence indented under it): that is how most skills in the wild are written, and skipping it left half the rows naming themselves and saying nothing. A YAML dependency for one scalar would be the largest thing in the file.

**A harness with no commands says so, and that is the `/` picker's one empty state.** `menuOpen` wants rows, so a list that is empty for good left the picker silent — and a `/` that does nothing reads as Dray broken rather than as this agent having none (DRA-217). One line is drawn instead of rows, naming no agent: a machine with no skills installed puts Codex and fx in the same state and the reader's question is the same either way. **Gated on the probe having answered**, which is what `useSlashCommands` returns `loading` for: Claude Code's ~1.5s cold read would otherwise flash "publishes no slash commands" over a list about to land. **A *failed* probe stays pending forever** rather than answering empty — an unreachable CLI is not a CLI with no commands, and saying the one in the other's words is a claim about the agent made out of a failure to reach it. The picker then simply never opens, which is what it did before there was anything to say. **The answer carries the key that produced it**, since `cwd` and `harness` move mid-render and state alone handed the previous harness's commands to the picker for the frame before the effect caught up — the same flaw `modelsByHarness` names, and the cache is read *during render* for the same reason the issue caches are. A query matching nothing still closes the picker quietly — that list is on screen, so its emptiness needs no narrating. `PickerMenu` takes the sentence as `emptyNote` beside `loading`, and drops `role="listbox"` where it is all there is, a box holding one unpickable line being no list.

**`@file` is the same bargain and needed even less.** The CLI parses `@path` out of the prompt itself, reads the file and injects it as a system reminder *before* the model turn — no tool call, no new event, nothing to map. A path that doesn't exist is ignored rather than failing the turn. Unlike a command, a mention is a word *inside* a sentence, so [mention.ts](../src/lib/mention.ts) finds the token around the caret rather than keying off position zero; the email guard falls out of that walk for free, since scanning back from the caret stops at whitespace, so landing on `@` proves it opens a word. A path containing a space can't be mentioned — the CLI's limit, not the picker's.

**The file list is an in-memory index, not a spawn per keystroke.** [files.rs](../src-tauri/src/files.rs) wraps [`fff-search`](https://github.com/dmtrKovalenko/fff), which walks the tree once on a background thread. Speed is not the only reason: typo tolerance, path-segment matching and git-status ranking come with it, and the last is what makes **an empty query the right thing to open on** — a bare `@` lists what the current turn has been touching. A filesystem watcher keeps the index current. Two limits are deliberate: `SharedFrecency::noop()`, since the crate's tracker is an LMDB store fed by a host editor's access log; and `MAX_INDEXES` capping live indexes at four. **An index unused for ten minutes is dropped** (`IDLE_DROP`): each holds a recursive FSEvents watch — on a project root that covers every `.claude/worktrees` build dir under it, so a sibling session's `cargo build` costs this process CPU — and a debouncer thread that wakes every 25ms whether anything changed or not. Everything touching the index goes through `spawn_blocking` — search holds a `parking_lot` read guard across the whole scoring pass, which must not be held across an await.

**Attachments are two features, because two kinds travel two ways.** [attachments.rs](../src-tauri/src/attachments.rs) decides which from extension *and* size together, so the composer's tile and the wire can't disagree. **Images** — png/jpeg/gif/webp under 5MB — become a base64 `image` content block alongside the prompt. Anything else becomes an `@/abs/path` mention appended to the prompt text, so it needs no wire surface at all; that cheapness is also why an oversized or unsupported image *degrades* to a mention rather than failing the send.

- **Only paths cross the bridge.** `read_attachments` hands the composer a thumbnail as a `data:` URL; `send_msg` takes back a path and re-reads the file.
- **Images are copied into `~/.dray/attachments/<session-id>/` before the path is recorded.** Persisting base64 instead puts megabytes into an append-only log read whole on every open; pointing at the original breaks the transcript the moment a screenshot is cleared out of `~/Downloads`. Loaded through `convertFileSrc`, hence `assetProtocol` scoped to exactly that directory. Non-image files are deliberately **not** copied — their mention has to name a real file in a real tree.
- **The drop target is the window.** Tauri intercepts the native drop before the webview sees it, so there are no HTML drag events to bind; `onDragDropEvent` reports paths, not `File` handles.
- **A queued prompt's attachments ride its queue entry**, resolved, handed over by the composer at send. `QueuedMessage.attachmentPaths` is deliberately *unresolved* so a cancel gives back what the user typed, so the row would otherwise describe them a second time — and holding them anywhere but that state gives them a lifetime free to disagree with it. Images draw through `ImageRef.url`, never `path`: the archived copy the asset scope allows is written at flush. A file draws nothing, since its `@path` mention is written at flush too and the delivered bubble has no tile for one either.

**A picture a tool hands back.** `Read` of a `.png` comes back as an `image` content block and nothing else. **The bytes arrive twice on one line**, and one copy was being persisted: the result carries an `image` block *and* the line's `tool_use_result` sidecar carries the same base64 at `file.base64`, which went straight onto `ToolResult.structured` — a screenshot session was 12MB of base64 in a 14MB log, read whole on every open and drawing nothing. The mapper now reads the block and `strip_image_bytes` drops the sidecar's copy. It mints an `ImageRef` carrying a `data:` URL, then `archive_result_images` in `read_stdout` decodes, writes and swaps the URL for a path **before emit**, so live and replayed transcripts load the same file; `read_stdout` strips the URL before the log write. **A call carrying a picture leaves its group** — "Read 3 files" is an honest summary of three files and no summary of three screenshots.

**The picker is one menu that must not take focus.** Every other composer control is a Radix menu focusing itself on open; this one can't, since the editor has to stay focused so typing keeps filtering. So [PickerMenu](../src/components/composer/PickerMenu.tsx) is a plain positioned listbox and every key it answers to is handled by `ChatInput`'s own `onKeyDown`. Enter completes the highlighted row instead of sending — the single place the Enter-sends rule gives way. Both pickers are that one component, and they are **mutually exclusive without arbitration**, since the caret sits in exactly one token.

- **The composer and the transcript share one segmenter** ([highlight.ts](../src/lib/highlight.ts)). What the composer draws and what `UserMessage` draws must agree about *what is marked*, or a word coloured while typing goes plain once sent. `highlightSegments` concatenates back to the input exactly, and the test asserting that round-trip is what the whole thing rests on.

- Four commands are withheld from the picker in `commands.rs` — `clear`, `fast`, `model`, `rename` — because the app already owns what they do and none of their effects come back on the wire. See _Known issues_ for why hiding them is a stopgap.

## The composer is a contenteditable, and the value is still a string

**[RichInput](../src/components/composer/RichInput.tsx) replaced a `<textarea>` and the mirrored overlay painted over it.** The overlay existed because a textarea shows its value character for character and cannot style part of it — a second copy of the text, held in register by a shared padding constant. That tie is also why `&Title (uuid)` put 36 characters of address in the reader's sentence. Breaking it is the point: a placed tag is drawn as a `contenteditable=false` chip whose *face* is short while `data-tag` holds the run whole.

**Reading the tree back yields the string that built it, exactly** ([readValue](../src/lib/richDom.ts)). Everything else here is in service of that, and anything breaking it sends different words than the reader typed. Two shapes are load-bearing: a newline at a block boundary, since a browser left to itself answers Enter with a `<div>`, and a **trailing `<br>`, which is two different things position alone cannot tell apart** — the placeholder every browser leaves so an empty line has something to draw, and a real break. What separates them is what precedes it: nothing, or another break, means placeholder. Reading every trailing one as nothing is what lost the newline ⇧⏎ had just inserted.

**A tag chips once the word is finished and the caret has left it** ([placeSegments](../src/lib/richText.ts)). `@s` is already a mention to the parser, so chipping on the parser's word alone would rebuild the DOM under the reader on every keystroke of a path — the overlay's own fragility. A caret *at* either edge counts as inside, the end edge being where it sits for every character of a tag being typed. That is also the stated cost: a chip erodes character by character rather than deleting whole, since "caret at its end" means both *still typing* and *just backspaced onto it*.

**The subtree is uncontrolled while prose is typed.** React writes to it only when `chipSignature` moves — a text run growing by a character answers no, so the browser keeps its own caret and selection. **Nothing asks the browser to edit for it**: a change arriving from anywhere but the keyboard — a pick, dictation, a paste, ⇧⏎ — is computed as a string and drawn by `renderInto`, with the caret placed at the index it belongs at. `execCommand` was the other route and is gone. It existed to keep the browser's undo history, which a chip rebuild destroys anyway, and it cost the browser deciding what a programmatic edit *means*: `insertLineBreak` under `pre-wrap` adds a second newline so the opened line has something to draw, which put a character in the value nobody typed and left the caret a line above the text.

**Undo is Dray's own, and it has to be** ([pushEntry](../src/lib/richText.ts)). A chip appearing calls `replaceChildren`, and WebKit records its history against the nodes that were there — so after one rebuild ⌘Z restored a snapshot that no longer matched and took most of the sentence with it. Nothing repairs that stack and the rebuild is the feature, so the native one is refused outright: **every** ⌘Z is `preventDefault`ed, whether or not there is anything to undo. Entries are whole values, and consecutive single characters of one kind collapse into the entry they started, so a press takes back a word the way a textarea does. Per mount, and the editor is keyed by session — which is also what stops an undo in one session restoring another's draft.

**A chip's face is shorter than its run, and each drops something different**: a mention keeps the filename and trades `@` for the file glyph, a session tag keeps its title and drops the uuid, an issue tag keeps `#` and swaps the identifier for the title, elided. An issue title has **no closing delimiter** — `#DRA-53 Some title` runs straight into the sentence — so nothing can read its end back out of the text; `rememberIssueTitle` records what the picker wrote and `withIssueTitles` joins the two segments with it. The transcript answers the same question from the prompt's persisted `IssueRef`s, so a replayed message reads as it did live.

**Chips carry no `title`.** What one hides is a caret press away, and a native tooltip is the one kind this app does not use.
