# Opening the working directory

**A split button in the right panel's tab row** ([OpenInButton](../src/components/OpenInButton.tsx)) hands the session's `cwd` to an installed app; the left half opens in the app picked last, the chevron changes it. Detection is [apps.rs](../src-tauri/src/apps.rs), macOS only — everything else answers an empty list. It sits in the tab row because the directory belongs to the *session*, not to one tab's answer about it.

- **Detection is `read_dir` over known dirs, matched on bundle file name exactly.** `/Applications`, `/Applications/Utilities`, `/Applications/Setapp`, `/System/Applications`, `/System/Applications/Utilities`, `~/Applications`; first dir wins, so a machine-wide install outranks a user's copy. **Exact, never substring** — `Cloudflare WARP.app` is not `Warp.app`, and a contains-check lists it as a terminal that then ignores the directory handed to it. `resolve` is split from `detect` so order is testable with nothing spawned.
- **The table is the guarantee, not `CFBundleDocumentTypes`.** `open -a` names the app outright rather than asking Launch Services to rank a handler, so it reaches apps declaring nothing — MacVim declares no folder type and opens one fine.
- **Address is the bundle path, never the bundle id.** `open -b` hands the id to Launch Services, which picks whichever copy it indexed. Names are no good either, since two builds of one editor differ by path alone.
- **Finder is the file default, and it *reveals*.** Every failure lands there too, so the worst a click does is what the link did before the setting existed. `pickFileOpener` therefore falls back to Finder, not the first editor — a transcript row has nowhere to put an error sentence, so a failure must be a working link.

## File links

**Three surfaces, one component.** [FileLink](../src/components/chat/FileLink.tsx) draws a tool row's filename, the reader's own `@mention`, and an absolute path an agent wrote into a sentence. The last is drawn the way the mention is — `@name:12` in mention colour, full path on the tooltip (`FilePathSpan` in [Markdown.tsx](../src/components/chat/Markdown.tsx)) — where a link the agent *wrote* as `[label](/path)` keeps its label and Streamdown's anchor look. It is a span with `role="link"`, never a button or anchor, because the tool row's copy sits *inside* the row's expand button — a second interactive element there is invalid markup and a click toggles the row instead. `stopPropagation` on click **and** on key.

**Mentions resolve against the session cwd**, joined in [filePath.ts](../src/lib/filePath.ts) onto [ChatCwdContext](../src/hooks/useChatCwd.ts)'s value — context, not a prop, since the only reader is four components below `Chat`. No cwd means the mention stays inert coloured text; resolving against wherever the app happens to run opens the *wrong* file. **A fork records the parent's cwd on every copied prompt** for the same reason — a fork carries the conversation into a *different* tree. `repoint_events` sets `user_message.cwd` with `get_or_insert`, not a plain set, so a fork of a fork keeps the *first* ancestor to record one.

**Paths in prose are a rehype pass, after sanitize and before harden** (`rehypeFilePaths` in [markdownPlugins.ts](../src/lib/markdownPlugins.ts)). After sanitize or it strips what the pass adds; before harden or the href is already rewritten. **Second plugin list, not a flag** — an issue description or PR comment names paths from somebody else's checkout, so `linkFilePaths` is on `AssistantMessage` alone.

- **Relative paths are marked too, as written, and resolved in `FilePathSpan` against the chat session's cwd** — the pass has no working directory, and resolving against wherever the app runs opens the wrong file. Same `findPromptPaths` the bubble reads, so the two surfaces link the same words; no cwd leaves the run inert mention-coloured text, a mention's own resting state.
- **A markdown link whose href names a file, absolute or relative, is *converted*, not descended into** (`anchorToFile`), keeping the anchor's children, and checked **before** `NOT_PROSE` — a link that is not converted is left whole, so a path inside a real link's label stays plain rather than nesting two links.

**The match rule is written to under-match** ([findFilePaths](../src/lib/filePath.ts)). A path must *open* a word, hold two segments, and carry no `//` — the letter-then-slash rule keeps `https://host/a/b` and `and/or` out, the two-segment rule keeps `/compact` out. `pre` and `a` are skipped in the walk. Nothing asks whether the file exists, so an over-match costs a dead click, not an error.

- **A path holding a space is dropped, not halved** — a half is a *real* path that can exist and open the wrong directory. The read runs forward to **end of line**, not one word.
- **"Whitespace" is the same set on both sides**: the match stops on `\s`, the forward read resumes on `[^\S\r\n]`, so tabs and non-breaking spaces break a path exactly as spaces do (`&nbsp;` in agent HTML is ordinary input).
- **Trailing `:12`, `:12:5`, `:L12`, `#L12` are stripped from the *path* before it is judged, and kept on the *match*.** The app's own harness prompt asks for `file_path:line_number`, so the whole reference is one link — a link stopping at the filename with `:12` dangling beside it in plain text read as half-converted (DRA-180). After punctuation stripping, before `isFilePath`, so `/a:12` is still refused rather than conjured into a path. The line rides `FilePathMatch.line` → `Segment.line` / `data-line` → `FileLink` → `openFile`, where `lineUrl` in [openWith.ts](../src/lib/openWith.ts) asks a known editor through its own URL scheme (`open -a <bundle> -- vscode://file/…:12`, verified against Cursor). An editor with no known scheme opens the file as before; Finder reveals and a line means nothing there.
- **The word straight after a break decides it wherever it can**: one holding a slash means the match was a truncation, one *opening* with a slash is a path of its own. Only past that word does the shape of the match matter — a match whose last segment holds a dot stops reading at one word, one without reads to end of line. The dot is a **guess**, so it only ever stops the read early, never accepts a match outright.
