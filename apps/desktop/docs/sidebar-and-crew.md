# The sidebar

**`session_created` carries an index item, never a `SessionSnapshot`.** The frontend's `agent_event` listener writes into sessions it already holds and *drops* events for ids it doesn't, so a snapshot would start a transcript in memory that later events could miss. An index item leaves the transcript unread until the row is clicked. `session_status` and `session_title` still land, since both write by id into maps the sidebar reads. **The row appears and is deliberately not selected** — the user is mid-conversation in the session that spawned it. The listener sits in a `[]` effect, so it needs `showArchivedRef`.

**Nesting is `sortSessions`** in [Sidebar.tsx](../src/components/Sidebar.tsx), exported and shared with ⌘⇧↑/↓ so the order stepped is the order drawn. **Walk depth-first, not one pass over roots** — the depth cap allows a spawned session to spawn, and a single pass emitted neither the grandchild nor anything below it, so rows vanished. A `seen` set means a cycle costs a strange order rather than a hung sidebar.

**The live list is stages, workspace-wide, and draws no project headings** (#516) — needs you, unread, idle, unread with an open PR, open or draft PR (ready to merge included), checks running, merged, set aside. Needs you wins whatever the PR says, running checks outrank a running turn, and a row mid-turn otherwise sits where it would rest. Draw order is also strength, so a nest takes whichever of its rows sits highest. This reverses the older rule of states *under* each project: past three sessions, the answer to "what wants me" was scattered under every heading. The PR stages read the sidebar's own marks, so they cost no `gh` call; a merged PR holds its session unread or working, so follow-up on landed work stays together, and failing checks stay in the open-PR stage, the red glyph saying the rest. Checks running sits near the bottom on purpose, since nothing is asked of the reader until CI answers. **Mid-turn is not a state of its own**: the row already says so where its timestamp would be, and a run for it moved a row twice for one piece of work, out on send and back on the turn ending. **A nest takes the strongest state anything in it holds**, so a child blocked on a question carries its parent up rather than the run that says "these want you" missing the only session in it that does. `asking` is read ahead of the backend's status, which still says `in_progress` and is right to. Live status falls back to the item's own field, which is what carries a `completed` across a restart. **The settled list passes no live reading at all** and collapses back to one run per project — it is a history, not a worklist — and **draws no Pinned group either**, since a pin is what the reader keeps in reach while they work and every row over there is done with. **Neighbouring single-row stages share one break**, within two families — needs you with unread, and the four PR stages — since a run of one row between two breaks reads as a heading rather than as a row, and each row's own mark tells them apart. An empty stage is skipped, its neighbours touching on screen; a stage of two rows cuts the run. **A list under three rows is not split at all** (`STATE_SPLIT_MIN`) — the split earns its break by making a long list quicker to scan, and there is nothing to scan in two rows. Rows, not nests: the count is what the reader sees down the left edge.

**No run names itself.** The state is already on every row in it — the yellow rail mark, the green one, the working indicator — so a heading is a second copy of what the rows say, and eight of them turn a list of sessions into a list of headings. The break between runs is what says one ended, which makes that spacer the whole signal — and **it needs `shrink-0`**, since a bare height in a flex column collapses to nothing once the list overflows, i.e. on exactly the long sidebar it exists for. Every row beside it is held up by its own `min-h`. `sortSessions` takes the same reading as the render, or ⌘⇧↑/↓ steps rows where they used to be.

# The crew

**A fan-out is drawn beside the conversation that made it** ([Crew.tsx](../src/components/Crew.tsx), rules in [crew.ts](../src/lib/crew.ts)) — a fixed 320px column holding one strip per session this conversation started, expandable into a live transcript, with permission and question cards answerable in place. Membership is **derived, never curated**: `parentSessionId` on the index and nothing else, direct children only. A spawned session may spawn, and a flat list cannot say one row belongs to another, so a grandchild sat there as a peer of the session that started it.

**The main column keeps drawing the *anchor*, whatever is selected**, and that is the whole difference between this and the split grid. Selecting a row moves the composer, the right panel, the header and the view tabs to that child while the conversation stays where it was. Drawing the child in both places was the first shape and it made the crew a slower way to switch sessions — the same transcript twice on one screen, the second copy standing where the thing it was spawned out of had been.

**The anchor is settled during render off a ref, never in an effect.** An effect is a frame behind, and that frame draws the crew against the session the reader has just left. Clause order inside `crewAnchor` is load-bearing: **hold first, then ask whether the selection spawned anything**, or clicking a row with children of its own makes it the anchor, swaps the list and drags the main column onto it.

**It is held only for a move made from inside the crew.** Clicking a row is navigation within an arrangement the reader is standing in; the sidebar and ⌘⇧↑/↓ are them leaving it, and an anchor surviving those left the main column on the parent while the composer moved, so the sidebar click read as inert. `keepCrewRef` is armed by `focusSession` and **consumed by a selection changing**, so it is only ever set where one will — focusing the session already selected consumes nothing and would leave it armed for whatever came next. **⌘-click drops the anchor outright rather than leaving it to that consumption**, since the row it is pressed on is usually the focused one: no selection change is coming, nothing else in that render moves, so the leaving has to be the thing that *causes* the render which reads it.

**Three readings of one thing and the split matters.** `crewExists` is "this conversation spawned something"; `crewUp` is the **arrangement** — what the main column draws and where the composer points — and deliberately does not ask which view tab is on screen, since tab bodies hide rather than unmount and a flip to Files would otherwise swap the hidden transcript for the focused row's and swap it back on return, taking the scroll pin and the mounted turns with it both ways; `crewDrawn` is the column itself, and is the reading every gate on being **seen** takes (read-marking, eviction).

**One `setOnScreen` effect for the grid and the crew together**, since it takes the whole set rather than adding to it — two callers would each wipe the other's. The anchor rides along, or the sweep reads the session the main column is drawing as nobody looking.

**A card is on screen for every row of a drawn crew, and `setCrewSeen` is that set alone** (`crewSeen` in [crew.ts](../src/lib/crew.ts)). `setOnScreen`'s set is narrower and must stay so — it names the transcripts being *read*, which is what read-marking promises and what eviction is safe against, and a strip is on screen with its transcript unloaded. What this one answers is whether a card would land in front of the reader, which every strip does without being opened. **Never filtered by `asking`**: a crew child joins `setOnScreen`'s set through that flag, and the flag is set by the very event `announce` is asking about — so the reading there is one render behind the question, and a child needing permission got a notice card *and* then drew its own a render later, with the notice's click dragging the main column onto a session already on screen (DRA-277). Read for `asking` alone in `announce`: a **completion** opens no row, so the strip's title turns green over a turn still unread and that one still announces. **The sound still plays; only the card is withheld.** This is not the table's "on screen" case — the crew is watched out of the corner of the eye, and a card opening itself in a column the reader is not reading is a change with nothing to say it happened. The card is the half with nothing left to do: a click has nowhere to go that is not already there.

**A `useLayoutEffect`, where `setOnScreen` beside it is an ordinary one, and the difference is which way being wrong costs.** That set only widens what is kept in memory; a stale reading here *suppresses* a notice, so it has to be exact in both directions and neither of the ordinary two is. An ordinary effect lands after paint, so a crew put away with the chord or flipped behind another view tab goes on naming its rows for a frame and an ask arriving there is silenced with nothing on screen to silence it for. A render-time write — which `crewRef` beside it takes, and which is right for a value read during render — is the opposite hole: React may interrupt or throw a render away, leaving this describing a column that was never committed. A layout effect runs inside the commit and before paint, so what it publishes is always what was committed and there is no frame in which the reader and this ref disagree; an event listener is a task and cannot land in the middle of one.

**The card scrolls itself into view, which is what makes the suppression honest.** The column scrolls and a card opens its own row, so on a fan-out of any size it can arrive below the fold — and `announce` has by then taken a drawn crew as the reader having seen the question. `PendingCard` answers that by making the reading true rather than by weakening it back into a second notice: `scrollIntoView({ block: "nearest" })`, keyed on the request id, so a card already in view moves nothing and a re-render does not scroll.

**A strip draws the newest two turns and mounts nothing above them** (`CREW_TAIL` in [turnWindow.ts](../src/lib/turnWindow.ts)) — no backfill, since a strip is a look in on work happening elsewhere and ⌘-click is there for reading the rest. **Turns, not rows**: a row count cuts mid-turn, and a fragment with no prompt over it answers none of the question a strip is for.

**Beside the chat only where it fits, and the fit reads minimums alone** (`crewBeside` in `App`): chat floor + crew + sidebar (drawn width, floored at its minimum) + panel floor, each side pane counted only while open — the panel under the anchor's key, as the crew would leave it, since `panelOpen` itself is derived from `crewUp` and would loop. The crew never gives width back, so on a half-screen window it crushed the sidebar to a sliver whose rows spilled over the transcript. Reading the sidebar's *drawn* width instead would chase itself, the crew's floor being what clamps it. Where it does not fit it starts hidden, and ⌘⇧C draws it **stacked between the transcript and the composer**, held to the composer's `max-w-3xl` column and capped at five closed rows (40% of the height once a transcript is open in it). The hint rides the first row's right side where the list is `@lg` wide, a container query on the stacked wrapper, and falls back to its own row under the list. A hidden stacked crew draws nothing, hint included; widening the window moves it back beside on its own. **Up to 1512px — a 14" MacBook — an open right panel stacks it even where the minimums fit** (`CREW_STACK_WITH_PANEL_W`), since four panes at their floors read as cramped rather than as fitting; that case starts **shown**, being a crew that fits and is only drawn elsewhere. An explicit toggle outranks the default either way.

**Rows are newest first by `created`, not `modified`.** The sidebar's ordering moves a row every time its turn ends, which here would slide an open transcript out from under somebody reading it.

**The column scrolls, hint and all, and open strips carry a floor.** `flex-1` shrinks to nothing before a flex container agrees to overflow, so enough closed rows would squeeze every open one down to its own header. The chat column's own floor takes the crew's width too ([ResizeHandle](../src/components/ResizeHandle.tsx)) — it is fixed-width and never gives any back, so without that the side panes could be dragged until the transcript was a sliver with the floor still reporting itself honoured.

**A card opens its own row; the reader's `open` set records only what they asked for.** That is what lets the toggle promote a card to its transcript, and what keeps a question from counting as a transcript somebody chose to read.

**⌘⇧C toggles it and there is no button**, kept per anchor and in memory, the right panel's own bargain: what the column holds differs from one conversation to the next, so putting away a fan-out of six says nothing about the next one. A permanent control in the titlebar would be chrome for a thing most conversations never have — so the chord is taught at the foot of the list instead, which is the only thing standing between a reader and a column they cannot get back.

**An edge rather than a divider, and no heading.** A *flat* border is what a split draws between two places to work, and this is one place with a list beside it — so there was none at all for a while, and then one drawn only while the right panel was out. What it is now is a `border-image` ramp in `--border`'s own colour, full strength at the composer's end and gone by the top: that reads as the column having a side rather than as the screen being cut in two, so it needs no condition and there is none. `border-image` rather than a gradient on a pseudo-element, since this column **scrolls** and an absolutely-placed child is positioned against the padding box and slides away up the list. The fixed width and the rows' own marks say the rest.
