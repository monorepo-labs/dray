# Transcription

**Dictation is local, and the engine is somebody else's.** [transcribe-cpp](https://crates.io/crates/transcribe-cpp) run the GGUF model, `cpal` capture, `rubato` resample. **The engine is not Handy** and the two must not be credited as one thing: `transcribe-cpp`/`transcribe-cpp-sys` live at `handy-computer/transcribe.cpp` under their own notice (`Copyright (c) 2026 The transcribe.cpp authors`), where the [Handy](https://github.com/cjpais/Handy) app is `cjpais/Handy` under `Copyright (c) 2025 CJ Pais`. Two entries in [THIRD-PARTY-LICENSES.md](../../../THIRD-PARTY-LICENSES.md), and a claim that one notice covers both name the wrong holder. **The only Handy files in this tree are the two dictation sounds.** Nothing tracks Handy releases because nothing is vendored from it; the engine update through Cargo like any dep. Handy's *app* code deliberately not taken: global hotkey, text injection, tray, history — Dray own the composer, so the words have nowhere to travel.

**No model ship with the app, and first press download nothing.** Weight is 218MB–886MB; pulling that on a press meant to start talking = not a thing to do to somebody. `start_transcription` answer `false` where no model ready, `stop_transcription` answer `NeedsModel`, and frontend open Settings on the Transcription tab. That the whole first-run flow.

**Backend is a *build-time* choice.** `Cargo.toml` turn `metal` on under `cfg(target_os = "macos")` and off elsewhere, so `Backend::Auto` resolve to GPU on Apple Silicon and CPU everywhere else. Nothing at runtime can change it — why there is no accelerator setting. **cmake is now a build dependency**; `transcribe-cpp` drive it through the `cmake` crate.

**Weights come from HuggingFace, pinned to a revision.** [catalog.rs](../src-tauri/src/transcription/catalog.rs) = the list, compiled in. Not `blob.handy.computer`, which is Handy's own CDN — same files, but their bandwidth is not ours to spend. `resolve/<revision>`, never `resolve/main`, or the bytes move out from under the `sha256` and every download fail verification at once. Catalog change = manual edit; nothing tell us when a better model land.

**Recommendation read the arch, where Handy's is editorial.** Their `recommended_rank` is a static catalog field and nothing there probe hardware. `recommended()` answer Parakeet Unified EN on Apple Silicon and Canary 180M elsewhere. Suggestion only — every model stay selectable.

- **Installed = present at the catalog's exact size.** Hash is checked once, before a fresh download is renamed into place, never on the settings read — hashing 700MB every open is felt. A truncated GGUF **load far enough to produce garbage** rather than erroring, which is the failure the size check exist for.
- **Download land via `.part` + rename**, so the real path only ever hold a file that already passed verification. A killed process leave a `.part` and nothing [`is_installed`] would believe.
- **Progress is an event, not a return value** — a download outlive the dialog that started it, so closing settings must not cancel it and reopening must find it running. Emitted every ~4MB; one event per chunk = thousands of round trips for a bar that redraw at screen resolution.
- **The loaded `Session` is cached across dictations** and dropped on model switch or delete. Loading is seconds; a session dropped per recording put that on every press. `Session` is owned and `Send` (hold `Arc<ModelInner>`), so it cache directly with no self-referential struct.
- **The load start on the press and the model leave after ten idle minutes.** `Live::start` warm it from `start_transcription` alone — the reader talk for the whole load, so it usually land before they press stop. It used to run at launch and on every model change too, which kept 731MB of Parakeet resident for a reader who never dictated (measured: the main process sat at 819MB). `Engine::touch` on every warm and transcribe bump a use counter and spawn a sleeper for `IDLE_UNLOAD`; a sleeper waking to a moved counter exit, one waking to its own empty the slot. **Check and clear under the `loaded` lock, and no `generation` bump**: split, a press slip between the two; bumped, a transcribe that took its token a moment earlier refuse to load and bail with "model changed", where an empty slot under a live token just reload. So the first dictation after a quiet spell may wait on a load, and every one inside the window is instant. **A warm load run with the lock released and install under a generation token, taken by `Live::start` before it spawn**, and **one loader mutex both warm and transcribe queue on**, or a press and its stop a second later pull the same several hundred megabytes twice. `unload` take neither, so switch and delete stay instant while a load run. — held across the load it would stall the `unload` a switch or delete is waiting on, and installed blind it would put a deleted model back after that unload cleared it.
- **Device is stored by *name*, never cpal's enumeration index.** Handy store the index; it shift on USB replug and silently start naming a different device. An unplugged stored device fall back to the system default rather than refusing to record.
- **Audio must be 16kHz mono `f32`.** No device offer that. Convert once at the end, never per callback — the audio callback is a realtime thread where allocating risk a dropout, and a dropout is a word the reader has to notice is missing. Stereo **average** both sides rather than taking channel 0, since a mic wired to one side alone record silence otherwise.
- **A denied microphone is *silence*, not an error, and that cost a whole round.** macOS open the stream, fire every callback and fill each one with zeros. First build transcribed those zeros to `""` and did nothing — reading exactly like a broken model, with no log line anywhere. Two things fix it and **both** are needed: `tauri-plugin-macos-permissions` raise the real prompt on `start_transcription`, and `Recording::finish` answer `None` where every sample is under `SILENCE_PEAK`. Verified by probe: 192000 samples, peak `0.000000`.
- **Every way dictation can fail is a *message*.** `TranscribeOutcome` carry `NoAudio`, `Empty` and `Failed` beside `Text`/`NeedsModel` precisely so none of them can collapse back into "nothing happened". A silent failure here is indistinguishable from the feature not existing. `Failed` was an `Err(String)` and is the one that escaped the rule; its message is `{:#}`, since `to_string` on an `anyhow` chain print the outermost context alone and every model failure read as the bare words "transcription failed".
- **The audio outlive the run, and that is what make a failure survivable.** Samples used to go into the engine **by value**, so a failed run drop them and the only cure was saying the whole thing again — ten minutes of speech gone to a model that could not load. Every stop now park a 16-bit WAV in `~/.dray/recordings/` ([recordings.rs](../src-tauri/src/transcription/recordings.rs)) *before* the model is even resolved, at any length, and the file is deleted the moment the model answer. `Failed` and `NeedsModel` carry the path, `retry_transcription` read it back through the **same** `transcribe_audio` a stop use, and `DictateControl` draw Retry and Show beside the mic while one is held.
  - **Deletion is on the model answering, not on words arriving.** `Empty` is a verdict — the model read the audio and found nothing in it — so it clear the file like `Text` do. Only a run that could not answer keeps one.
  - **Saving is best effort and the path is `Option`.** A full disk must not take down a dictation that would otherwise work, so a failed write log and carry on; `audio_path: None` is the one failure with nothing to retry, and the message say so.
  - **`recordings::read` refuse any path outside the directory.** The path arrive from the frontend and this command open a file and feed it to a model, so the directory is the only thing saying which files it may.
  - **16-bit PCM, not the captured `f32`.** Half the size of something reaching hundreds of megabytes, playable by anything the reader open it with, and the quantization sit ~96dB below what an ASR model read. Chunks are walked rather than a 44-byte header assumed: a header read at the wrong offset yield audio that transcribe to *nonsense* instead of failing.
  - Unclaimed recordings are pruned after 7 days, on write — the one moment something is definitely being added. Nothing else sweep them.
- **Struct-variant fields need `rename_all` on the *variant*.** The container's rename name variants; a struct variant's own fields stay snake case without it and cross the bridge as `audio_path`, which read as `undefined` and fail nothing.
- **Two files gate the mic, and each fail differently.** `NSMicrophoneUsageDescription` in [Info.plist](../src-tauri/Info.plist): macOS **kill** a process reaching for the mic without one rather than refusing it, so its absence present as the app vanishing on first press. `com.apple.security.device.audio-input` in [Entitlements.plist](../src-tauri/Entitlements.plist): Tauri's bundler sign **every** build with the hardened runtime, ad-hoc `-` included, and under it TCC refuse before the prompt stage — no dialog, no row in Privacy & Security, `check_microphone_permission` just answer false. The plist key being present prove nothing about this one; `codesign -d --entitlements - Dray.app` is what to read. `tauri-build` embed that file into the dev binary's `__TEXT,__info_plist` section too, so the string *is* there under `tauri dev` — read it with `otool -X -s __TEXT __info_plist`, remembering the words come out little-endian.
- **Dictation cannot raise its permission prompt under `pnpm tauri dev`, and the reason is not the plist.** The dev binary is a bare Mach-O, not a bundle, so TCC attribute its request to the nearest **responsible ancestor** — walk `ppid` and it land on whichever GUI app started the chain. Running Claude Code inside Dray, that is `/Applications/Dray.app`, whose *shipped* plist carry no microphone key, so the request is refused **silently, no prompt**. Two ways it break: a detached launch (`nohup`, `&`) reparent to `launchd` and leave **no** responsible app at all; an attached one inherit an app that may not declare the key. **Test dictation from a bundle** — `pnpm tauri build --debug --bundles app` — which is its own responsible process and prompt properly. Same shape as the notification banner's `is_dev()` guard, different mechanism.
- **Engine is fine; suspect capture first.** Parakeet transcribed a `say`-generated WAV word-perfect on the first try. When dictation "doesn't work", probe the microphone before the model — a standalone `cargo run` reading `/tmp/tts.wav` settle it in a minute. `transcription::bench::stop_to_text` is that probe, `#[ignore]`d, timing each stage on a WAV (`DICT_CLIP`) — run it `--release`. The first load after a cold boot took 11.7s once, then 0.35–0.47s every time after, new binary included.
- **Pauses are cut before the model reads the audio** (`trim_silence`, [earshot](https://github.com/pykeio/earshot) VAD, Handy's idea and timings): 64ms of voice opens speech, ~460ms is kept either side. A 56s clip with 26s of pauses went from 2.0s to 1.1s and transcribed *better*. **The trim runs inside the engine, never at the stop**, so the parked WAV is the whole recording and a retry trims it afresh. **No speech found sends the whole recording**: the detector missing quiet speech costs the old speed, never the words.
- **A model that streams decodes while the reader talks** ([live.rs](../src-tauri/src/transcription/live.rs), Handy's idea; Parakeet Unified and Nemotron in the catalog, read off `supports_streaming`, never a table). A worker borrows the session out of the slot for the recording (`Engine::lend`/`give_back`), pulls the buffer every 160ms and feeds the stream **speech alone, through the same `Gate` the batch trim uses**: fed every sample, the stream dropped the first word after an 8s pause. Stop to text went from ~1.1s to ~0.3s on the 56s clip, text identical. Models that cannot stream stay batch. **Every failure ends in the batch run, inside the worker, on the lent session**: a load landing after the stop (the stop's unread backlog past 2s), a stream error, an empty answer. A batch run anywhere else would find the slot empty and load a second copy — so **a load meeting a lent model waits for the `Loan` to drop** (an Island retry mid-recording runs after the stop), and the `Loan` is RAII so a panicking worker cannot strand it. **The session goes back before the stop hears anything**, for the same reason. **A cut sends its worker message under the recording lock**, or a stop's take and message can overtake it and the worker closes the wrong stretch with the wrong tail. **A take hands over the unread tail and holds pulls** (`Tap::take`/`release`) until the worker closes the stretch, or a cut's next stretch leaks its first samples into the stream being finalized. `live_stop_to_text` is the end-to-end probe: the clip played into a fake capture in real time.
- **The mic hear the speakers, so recording mute them.** One toggle, `muteWhileRecording`, on by default. Moved through `osascript`'s `set volume output muted`, since that is the documented way at the *system* output where CoreAudio want a device lookup plus a property write per channel. Four thing it rest on: the prior mute state live in a **module static**, not on the `Recording`, since a recording dropped rather than stopped must still put the sound back; a second mute **keep the first reading**, or the machine get restored to our own `true` and stay silent for good; restore put back **what it found**, never a flat unmute, since a reader already muted before they spoke stay that way; and restore **clear the record only once the machine is actually back**, since taking it first mean one failed `osascript` drop the only thing that know what to restore and every later stop find nothing to do. Quit is the other end of that record's life, so `RunEvent::Exit` in [lib.rs](../src-tauri/src/lib.rs) restore synchronously — quitting mid-recording is otherwise the one ordinary way to leave a machine silent. Best effort throughout — no output device answer `missing value`, which fail the parse and leave the machine alone. Mute land **after** `Recording::start`, so a refusal never touch it, and restore land the moment the mic close, not once the model finish. **The mute waits 700ms past the mic opening, so the start tone is heard** (`START_TONE`): it once landed at once and swallowed the tone, which read as dictation not starting. The mic hears the tone, which is no speech. The wait is a ticket (`arm_mute`) checked under the lock a restore takes, and every restore moves it on, so a stop or cancel inside the 700ms leaves nothing to mute later — taken outside that lock, a stop between check and mute would restore first and leave the machine silent. **Lower-the-volume was built and cut**: a three-way picker where the honest answer is one switch.
- **The composer take focus when the words land** ([composerFocus.ts](../src/lib/composerFocus.ts)). One module-level element registered by `ChatInput`'s own `ref`, same gap `useDraft` name and same fix: the recorder live in `App` and the mic button live in `ComposerToolbar`, so neither can reach the editor through props. Only where the reader is still on the session they spoke into — a dictation outlive the screen it began on, and focusing a composer holding somebody else's draft is worse than not focusing. The caret is **left where it was**, since a draft grow at the end.
- **Transcript append to the draft, so `useDraft` is now a `useSyncExternalStore`.** The controls reach `ChatInput` as an opaque `ReactNode` — same gap `useAttachments` name, same fix. `appendToDraft` join with a space unless the draft already end in whitespace, so dictating after typing continue the sentence and never eat it.
- **The destination session is pinned when recording *starts*, never read at the end.** The recorder is app-wide and a recording outlives the screen it began on, so handing `onText` the live `selectedSessionId` filed the words under whichever session happened to be selected when the model finished — dictate in A, switch to B, the sentence lands in B's draft, silently. `useRecorder` take a `target` and copy it on `start`. Switching away therefore **does not** cancel: the recording run on and the text is waiting in the draft it was spoken into.
- **One recorder, process-wide.** `TranscriptionState.recording` is a single `Mutex<Option<Recording>>` and `start_transcription` replace whatever is there, so two live streams cannot exist — both would fill buffers and only one could be read. The frontend state is global too, so a second session show the *same* recording rather than offering a new one.
- **Transcribing redraw the stop button, spinner in place of the tick.** Same filled circle, same place — the state after a press should say the app is working on what was asked, not that the control went away. A `span` carrying `buttonVariants`, not a disabled `Button`, since `disabled` dim the fill to half for a state lasting under a second.
- **Dictation is two sounds: Handy's own marimba pair**, copied under its MIT licence to `src/assets/dictate-{start,stop}.wav` and played frontend-side ([sound.ts](../src/lib/sound.ts), one `play(url)` shared with the notification and celebration clips) — no `rodio`, no Tauri resource, since the recorder's state already live there. `start` play **after** the refusals, or the tone announce a microphone that was never opened. `stop` play when the **words land**, not when the microphone close: the wait between the two is what the reader is listening for the end of. Only on `Text` — the other outcomes say their own piece, and the tone would be claiming something arrived. **Cancel is silent**, matching Handy, which ship no third sound. The elements are kept and rewound rather than rebuilt, since a fresh `Audio` decode on first play and put the tone behind the press.
- **Stop and cancel are two controls, never one.** They mean opposite things about the words just spoken. Handy get away with one key because it type into whatever window has focus; here the transcript land in a draft the reader can see, so throwing it away has to be deliberate. Escape also cancel, **ahead of every other Escape** in `ChatInput`, since recording is the only state holding a device open.
- **Send moved out of the text row onto the control row.** It spanned the whole card height beside the text before, which left nowhere for dictation. Now: text take the card's full width, and one row under it carry the toolbar left, dictate and send right.
- **The level is polled, not pushed** — `transcription_level` answer the loudest sample since it was last asked, ~20fps. A level is only interesting *now*, so a missed reading should be a dropped frame rather than a queued event arriving late. Written from the audio thread as an `AtomicU32` holding `f32` bits, never a lock the realtime callback could block on.
- **The visualizer is an envelope, not a spectrum.** One float cross the bridge and a fixed centre-weighted shape spread it across nine bars. Handy draw a real FFT, which want the whole buffer frontend-side; this tell the reader the one thing they need, which is that the mic is hearing them. **No `Loader2` anywhere here.** Its glyph is not centred in its own box, so rotating it trace a small orbit and read as a wobble at 14px. [Spinner](../src/components/ui/spinner.tsx) is ours: one circle concentric with the viewBox, `pathLength`-normalized so the gap is a share of the ring rather than `2πr` recomputed per size, and `animate-spin` on the **`svg`** — an SVG child's `transform-origin` resolve against the viewport, so a spin on the `circle` swing it around the top-left corner. Downloading draw its percentage over the bar it already has.
- **⌘D alone dictate**, through `useHotkey`'s `platformOnly`. `meta` normally accept either accelerator, which cost nothing for a chord no platform assign — but ⌃D is delete-forward in every macOS text field, including the composer this shortcut is for.
- **A finished download select itself where nothing is selected**, never replacing a working choice — a reader adding a second model to compare has not asked to switch to it. **A *cancelled* one select nothing at all**, and that need saying because a cancel answer `Ok` like a success: `download` return `Downloaded::{Installed,Cancelled}` so the caller can tell them apart. Without it a cancel pointed the setting at a file never written — the tab drew a tick beside a model the composer kept refusing to dictate with.
- **Deleting a model is confirmed in the row, not in a dialog** — a modal take the whole window over a file Download get back. **The actions sit on the bars' row, not the title's, and that is what make the confirmation cheap.** Beside the title they shared a line with prose that had to give up width for them, so anything wider than an icon re-wrapped the description and moved every row below — which forced an absolutely-drawn question over an `invisible` bin, and before that a reserved slot spending the widest state's width in all four. The bars are fixed-width and give up nothing, so the buttons grow into the gap and the whole problem go away. One `confirming` id in the parent, never a flag per row, or two rows ask at once where one press was made; picking any row clear it.
- **Dictation cannot be looked at under `tauri dev` at all**, so a composer demo page carried the controls for a while and was deleted, before demos were kept — see _Demo pages_ for the shape to rebuild it in. Testing the real thing want a bundle: `pnpm tauri build --debug --bundles app`.
- **The model list is a `radiogroup` and the whole row is the control.** A "Use" button beside a row that already look selectable was two ways to do one thing. Only an *installed, unselected* row is clickable — a row that look clickable and answer nothing is worse than a plain one, and a several-hundred-megabyte download is too big to trigger by clicking a row, so Download keep its own button. Buttons inside the row `stopPropagation`, or deleting a model select it on the way down.
- **`languages` is a phrase, not a count.** "4 languages" tell a French speaker nothing about whether the model is for them, so few languages get **named** (Canary's four) and twenty-eight or a hundred stay a number. Compiled into the catalog, since that is where the judgement belong. **A counted phrase link to the model's Hugging Face page; a named one link nowhere** — which-28 is a question only a count leave open, and "English, German, Spanish, French" have nowhere to send anybody. The row tell the two apart with `/^\d+ languages$/` rather than a second catalog field free to disagree with the first. Expanding the list in the row was the rejected alternative: long, and stale the moment the model gain a language.
- **`speed` and `accuracy` are Handy's catalog scores, copied not measured**, 1–100 and relative to each other — no benchmark was run here, and numbers that look measured would be worse than none. Drawn as bars for that reason: a figure invite a precision that is not there. (Handy's own UI draw neither today; the fields are in its `catalog.json`.)
- **Dropping a catalog entry orphan its file.** `installed_ids` only answer for ids the catalog still name, so a downloaded model whose entry is removed become several hundred megabytes with no row to delete it from. Nothing sweep the models directory.
- **Download cancel is cooperative, checked between chunks.** Aborting the task would drop a half-written file and a live hasher mid-flight; between chunks is the one place it can delete its own `.part` on the way out. The cancelled id live in a module `HashSet` and is **removed** rather than set false, so "cancelled" and "running" are one question. A cancel emit a closing progress event with **no** error, since it is what the reader asked for.
