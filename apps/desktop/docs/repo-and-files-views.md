# The repo view

**The main column has tabs, and Chat is one of them.** [ViewTabs](../src/components/layout/ViewTabs.tsx); `VIEW_TABS` is set *and* order, so Terminal later is one array entry plus one body plus one shortcut id — accelerators (⌘1 through ⌘4) are named per *view* rather than per slot, since a rebinding names the view and not its position in the row. The split view's panes take ⌘⌥ digits — they swapped places with the views, whose ⌘⌥ digits read as the rarer chord for the one most pressed. **A default that moves is listed in `PREVIOUS_DEFAULTS`** ([shortcuts.ts](../src/lib/shortcuts.ts)): only rebindings are stored, so a reader who had already bound a now-default chord elsewhere would have both fire on one press, and `yieldMovedDefaults` puts the moved row back on its old chord instead — the reader chose theirs, the build chose the other. Bodies use `TabBody`, so the transcript **hides, not unmounts** — scroll position, follow pin and highlighted diffs survive the flip. The tab is per session and **not persisted**. The composer is hidden off Chat, safe to unmount because `useDraft`/`useAttachments` are module-level.

The right panel's Changes tab stays and answers a different question: the panel is "what did this turn do", the view is the whole repository.

- **`head_tree` answers `None` for one thing only: not a repository.** A repo with an **unborn** branch answers the **empty tree** instead, the honest baseline there. `null` alone still says two things — "no repo" and "not asked yet" — so `useHeadTree` carries `settled` and the empty state waits on it.
- **The uncommitted list is the HEAD tree against a live snapshot** (`changes_since(cwd, headTree, None)`). A commit moves HEAD → a new tree id → the cache key rolls onto the new baseline by itself. **Nothing invalidates anything.**
- **Commit SHAs pass `is_tree_id` and every diff path takes them unchanged** (≤64 hex), so a commit's own diff is `useChanges(cwd, commit.parent ?? EMPTY_TREE, commit.sha)`. A root commit's parent is `None` and `EMPTY_TREE` (`4b825dc…`) stands in, so the first commit in history opens like any other.
- **The selected file is derived, never stored** (`find(path) ?? files[0]`), so a file that stops being changed can't leave the pane pointing at nothing.

**The view reads, never writes — and that is not "not yet".** The conversation next door is where work gets made and committed, so a second place to write commits is a second way to do what the reader is already asking the agent for. No checkbox, no message box, no push button, no discard.

# The files view

**A fourth tab beside Chat, Diff and Browser, and it reads for the same reason the repo view does.** A tree down one side, an editor's tab strip and a code pane down the other. No editing: the Docs panel edits markdown because a doc is the *reader's*, where code is the agent's and this view's whole promise is that it changes nothing. Design and what was left out are in [FILES-PLAN.md](../FILES-PLAN.md).

**Two commands and one generalisation.** `list_dir` and `read_file` join `files.rs` beside the `@` picker's index, and `watch_docs` takes a **scope**.

- **Order is VS Code's** — directories first, then case-insensitive by name. `.git`, `.svn`, `.hg`, `.DS_Store` and `Thumbs.db` are dropped, which is VS Code's `files.exclude` defaults and nothing else: `node_modules` and `target` list like any directory, **dimmed rather than hidden**, since a tree that hides what is on disk is lying about it.
- **`ignored` is `git check-ignore --stdin -z`, one spawn per listing.** Nested `.gitignore`s, `info/exclude` and the user's global ignore in one answer, which the `ignore` crate already in the lock file cannot give. Exit 1 means "none of them" and is an answer; only a non-repository or a git that will not run leaves every flag down. **The input is written from its own task** — git streams its answer as it reads, so filling both pipes before draining stdout is a deadlock on a big enough directory.
- **`isDir` is read off the link's *target*.** A symlinked directory expands like any other; a broken link lists as a file rather than as a folder that answers nothing.
- **`read_file` is `read_doc`'s three checks at a 4MB cap**, with images answered first as a `data:` URL — the asset protocol's configured scope is the attachments directory and stays so. **Videos (mp4, m4v, mov, webm) are the exception, answered before any size check**: too big for a `data:` URL and needing Range requests to seek, so `read_file` adds that one file, by its **canonical** path, to the asset scope at runtime (`allow_file`) and the viewer plays it through `convertFileSrc`. Canonical because the protocol resolves links before matching, so `/tmp/a.mp4` would read as `/private/tmp/a.mp4` and be refused. That widens nothing a page could not already read — this command hands the webview any file under the cap — and never the whole disk. **Kind is judged before size, or the message lies**: a video under the cap failed UTF-8 as "Not text" and one over it read as "too large", and a binary over the cap still says "Not text" (a NUL in its first 8000 bytes, git's test), since no cap would make it readable. The cap is four times the doc panel's because a lockfile is the file most likely opened here and the renderer already goes plain text past 100KB, so a big one costs scrolling, not freezing. SVG is an image here though `attachments.rs`'s table calls it a file: that table is the *model's*, and the API refusing an SVG says nothing about a webview.
- **`watch_docs` takes a scope and `WATCH` is a map.** The Docs panel passes `"docs"` and this view `"files"`. Without it the two silently take each other's watch away on every open, since the command replaces a scope's set outright; `doc_changed` stays shared, each listener already filtering on its own open set. It is also now **`#[tauri::command(async)]` over a synchronous body**: a plain command runs on the **main thread**, and this one builds an FSEvents watcher and drops the scope's previous one, a drop that joins that watcher's thread. Re-arming is every session switch since this view arrived, so the freeze it bought was one met while doing nothing unusual.

**`useOpenFiles` is `useDocs` without the draft half** — per session, module-level, `useSyncExternalStore`d, in memory only. The `opened` counter is what `App` flips the view on, for the docs panel's reason: reopening a file already on screen leaves the list unchanged, so only a count of clicks can say the reader asked. **`reveal` is a second counter and it is not redundant** — `line` alone cannot scroll, since clicking one link twice asks to be taken back to a line the pane is already sitting on.

- **The store speaks absolute paths, the tree relative ones.** A chat link can open a file from outside `cwd` entirely; the tree stays rooted at the session's directory and the header draws an outside file's path whole.
- **Reads adopt the file silently, always.** Nothing is compared and nothing can be lost, because nothing here edits — so an agent rewriting what the reader is looking at should move the text under them. `doc_changed`, the turn ending and the header's refresh all land in one function.

**The tree relists on the turn ending, and nothing polls.** Every *expanded* directory, one `list_dir` each, gated on the view being the one on screen. Expanding caches until that relist, so collapsing and reopening is free. **Rows are `flattenTree`'s flat list** ([fileTree.ts](../src/lib/fileTree.ts), pure and tested) because the keyboard works on a list: ↑/↓ are one step through an array where a nested render would have to walk a shape the DOM only implies.

**Every row is `memo`ized and the click handler is one stable function, and that pair is load-bearing.** This view re-renders on every session event — a streaming turn is one per delta — so a tree with a few hundred rows open otherwise reconciles all of them at the speed an agent types, which is how a view that only *reads* manages to freeze the window. An inline arrow per row defeats the memo entirely, so `activate` is a `useCallback` and `FilesView`'s `openRelative` above it is too. Both change only when the reader expands something or a relist lands, which is when the rows have to be reconciled anyway. **The cursor takes real focus with it**, which is what makes Enter honest — every row is a button, so the browser activates the focused one, and a cursor drawn beside a focus that stayed behind would open whichever row was clicked last. Enter is therefore **absent** from the key handler: handling it there too toggles a directory open and shut in one press. Not virtualised, deliberately — a tree that large is the reader's own doing and the Diff view's list draws the same way.

**The filter box is the `@` picker's index, so it is already built and already watched.** An empty box draws the **tree**, never a ranked list of everything — that is what an empty filter means here. The tree is **hidden, not unmounted**, while a query is up: the expanded set is what the reader built and clearing the box has to give it back. Escape clears and puts focus back on the tree **next frame**, since the tree is `display: none` until the clear commits and focusing that does nothing at all, silently.

**Two tabs with one basename get their parent appended** (`index.ts — changes`), computed in `tabLabels` over the whole list — a name only stops being unambiguous when a second file arrives, and the tab that has to change is the one already on screen. Closing the active tab activates its left-hand neighbour, or the right-hand one at the start. ⌘⇧←/→ step the strip, `skipInTextField` for the filter box; ⌘W closes the active tab, through `tab.close` in `App` rather than a binding here — see _Closing with ⌘W_.

**The viewer is `CodeView`'s `File`, full height, inside the library's `Virtualizer`.** Same shared Shiki, same worker pool, same `useHighlighter` gate with a plain `<pre>` meanwhile. The `Virtualizer` is the scroll container and its presence alone is what makes `File` a `VirtualizedFile` (`useFileInstance` reads the context), so only the rows in and around the viewport exist — measured on an 8452-line lockfile in Safari, 400 rows in the DOM against 16904, and a tab switch painting in ~56ms where it took 480–900ms (DRA-238). `overflow: "scroll"` is load-bearing there: it is the library's uniform-row path, nothing measured per line, and the default 20px metric is exactly the `--diffs-line-height` its rows draw at — set that variable anywhere and `metrics.lineHeight` must follow. **A line a link named may not be in the DOM yet**, so the mark scrolls the pane through `getLinePosition` when its row is absent, and the post-render that follows marks it; the plain `scrollIntoView` still serves a row already drawn. **The line a link named is marked through `onPostRender` plus `unsafeCSS`** — `[data-line-index="line-1"]` inside the host's shadow root, scrolled to centre once and given `data-target`, painted from the library's own `unsafe` layer the way `DiffPane` overrides its gutter. Zero-based on the wire, one-based to the reader; a line past the end marks nothing, which is the right answer for a stale reference.

**A chat link no longer leaves the app.** `openPath` sends markdown to the Docs panel and everything else here; **⌘-click is what still reaches the reader's own editor**, line and all — the same "out there, not here" the issue rows and transcript links already mean by it. `ChangesView`'s file rows are left alone: a diff and a file are different answers.

**One row, not two: the Open button rides the tab strip and there is no filename header.** The tabs already name the file, so a header under them said it twice — the reading the Docs panel's chip strip takes. **A tab carries no `title` either**: the full path on one drew a native tooltip, which is the app's own rule broken (chrome is a real tooltip or nothing) and read as a directory hanging off the cursor on a tab the reader was passing over. `tabLabels` appends the parent where a basename stops being unambiguous, which was the only moment the rest of the path was worth saying. The close cross keeps a real tooltip, and names ⌘W on the **active** tab alone — the chord closes whichever tab is active, so a background cross naming it would promise a key that closes a different file. **The button is `OpenInButton` wearing a second hat.** The split button the right panel hands a *directory* to now takes an [`Opener`](../src/lib/openWith.ts) — the key a pick is stored under, which apps are listed, which one stands in for a missing pick, and what opening even *means*. Directory and file differ on all four, and Finder most of all: it **reveals** a file and opens a directory. One control for both, or the reader would have two places to say which editor they use and they would disagree — and the file half has to resolve exactly as `openFile` does, or the button names one app while a ⌘-click in the transcript reaches another.

**The list's side and width are the reader's, in local storage** (`ade.filesListSide`, `ade.filesListWidth`). **It opens on the right**, against every other list in the app: the sidebar already holds the left edge, so a tree there puts two lists back to back with the code squeezed between them. The switch is one icon button beside the filter; the width is a drag handle, the first in the app, and it **writes on pointerup alone** — the value moves on every frame and only the last one is a preference. `setPointerCapture` is load-bearing: without it the pointer leaves the strip on the first frame and every move after that is delivered to the code pane.
