# Bots

**A bot is one ongoing chat with instructions and memory of its own, and everything it starts runs hidden and reports back to it after every turn** (#816, [bots.rs](../src-tauri/src/bots.rs), [bots.ts](../src/lib/bots.ts)). The shape Grok Bot, Cursor Projects, Claude Projects and OpenBot all ship: the reader runs everything from one chat and never switches sessions.

**A bot is a folder, and its session is known by running in it.** `bots/<id>/` under the home holds `INSTRUCTIONS.md` and `MEMORY.md`; `bots.json` holds the list (id, name, path). The bot's chat is an ordinary session whose `cwd` is that folder — no field on the index says "bot", so an older build reading the index loses nothing, and every reader asks `bot_at(cwd)` / `botAt(bots, cwd)` instead. The chat is the newest unsettled session there (`botSession`), so **Start fresh is settling it**: the next send makes another, with the same instructions and memory.

**Instructions and memory ride every harness's system-prompt slot** through `bots::system_prompt(base, cwd)`: Claude Code's `--append-system-prompt`, Codex's `developerInstructions` (on `TurnSettings`, restated on start and resume), fx's `systemPrompt`, grok's `rules`, pi's `--append-system-prompt`. Read at spawn, so **an edit reaches a running bot at its next start** — Settings says so. **Except on grok and fx**: both keep the prompt on their own session record and take none on resume, so there an edit lands only with Start fresh. No resume field was sent instead: neither has been seen to take one, and a refused open kills the session. The bot's own edits need no reload: it made them. Each file is capped at 16k characters, and a closing tag inside one is broken up so the text cannot end its block early. Memory is marked as data, not instructions.

**Everything under a bot runs hidden** (`create_session`, `in_bot_tree`): its children and theirs, whatever `--hidden` said. The walk is bounded at 8, so an index pointing a session at its own ancestor costs a wrong answer rather than a hung turn. A bot's folder is no repository, so a create inheriting it as the project is refused with "pass --project" rather than failing at the worktree in git's words.

**Every turn a child closes is sent to its parent, by Dray, not by the agent** (`report_to_parent`, from `ingest_event` on a main-thread `TurnCompleted`). A report the agent is asked to send is one it can forget — OpenBot's weak spot, whose delegation rules are prompt-only. It goes through `send_message`, the path `dray session send` takes, so the bot reads it exactly like a message the child sent. Only Claude Code fills `final_text`; the others say their answer in `AssistantText`, so the last one of the turn is kept (`LAST_REPLY`) and used instead. A turn with no text still reports, saying it failed or ended silently, and a child dying mid-turn reports from `settle_dead_child`, whose close never passes through `ingest_event` — so the bot is never left waiting. A settled child or a settled bot chat takes no report: sending would resume a conversation the reader closed. **Boxed**: the read loop calling it lives inside a harness's `init`, and the send can reach `init` again, so unboxed the compiler cannot name either future.

**The frontend.** Bots lead the live sidebar in a Bots section (`BotRow`: the session row's rail and orb, nothing else); their ongoing chats leave the session list (`inSidebar(items, bots)`), their settled ones stay in the settled list, the only way back to one. The section reads the active side of the index alone and is empty while the settled side is loaded. The space check spares anything in a bot's tree (`inBotTree`), or a task opened from the Tasks tab in another space's project closed at once. Opening a bot with no chat aims the empty composer at its folder (`handleNewBotSession`, not `handleSelectProject`, which would remember a bot as a project) and the toolbar names the bot in place of the project pickers; a send there takes no worktree. A bot's chat gets a **Tasks** tab after Changes: its children at any depth, grouped Waiting on you / Working / Done, off `crewRows` — which now walks every held session, not the space's, since a bot hands work to any project. Cards still come to the bot's chat (#807). Created and edited in Settings › Bots.

**Not built.** Bots live on This Mac's server only — `list_bots` asks the local one. No "instructions changed" line in the chat when the bot edits its own file; the prompt asks the bot to say so. Start fresh is the bot row's right-click menu, beside Edit in Settings.
