# Updates

**Shipping one = `apps/desktop/RELEASING.md` (gitignored, local only)** — follow it rather than reconstructing it from here. It says what to type and, more important, what to *check* after: a green tick proves nothing, since the bundler only warn when notarization fails.

**Two signatures, and conflating them is the first mistake to avoid.** The minisign keypair is the updater's own integrity check — public half in `plugins.updater.pubkey`, private half a build-time env var, and a bundle built without it is refused by every client. Apple's Developer ID signature is a different question: it is what stops macOS blocking the download, and says nothing about whether the payload is one this app published. Both set in [release.yml](../../../.github/workflows/release.yml); only the first is needed for a local build.

**A tag's shape pick the channel**, semver does the rest. `v0.3.0` stable, `v0.3.0-beta.1` beta, and because `0.3.0-beta.1` sort *below* `0.3.0`, beta users are offered a stable release the moment it ships with no logic reproducing that rule. What the release job encode is the other half: a stable release write both manifests, a beta release only `beta.json`, so beta is a superset, not a fork.

**Manifests only ever move forward** (`promote` in [release.yml](../../../.github/workflows/release.yml)). The beta line run *ahead* of stable for its whole life, so an unconditional `cp` let a stable hotfix overwrite `beta.json` with an older version. The guard is the same semver comparison the plugin makes, prerelease rules included, in inline node — **not `sort -V`**, which put `0.9.4-beta.2` *above* `0.9.4`. Equal versions rewrite; a missing manifest is written, never an error; a release moving nothing skip the commit.

**Bytes come from R2, never GitHub's release CDN**, which has had a 42MB dmg take 45 minutes. `release.yml` uploads each build under `<tag>/` and rewrites the manifest's URLs onto `vars.DOWNLOADS_URL` (the signature covers bytes, not the URL); the manifest job copies the dmg to the root `Dray_universal.dmg` (the site's download button) only where `stable.json` moved to this version, so an older release finishing last cannot regress it. The GitHub release still carries every asset, it just serves none of them.

**The channel is chosen per check, in Rust** ([updater.rs](../src-tauri/src/updater.rs)), so switching channels need no rebuild. It is owned by [useUpdater](../src/hooks/useUpdater.ts) and handed down as a prop — `useLocalStorage` is per-component, so a second copy in the dialog write a value the hook never sees, and `channel` is what re-arm the checking effect.

**Install is blocked while any session is mid-turn**, and the button waits rather than warning, since swapping the bundle relaunch the app. The check is `statusBySession` and is complete on its own, as no child survive a restart. It lives at the button, not in `install_update`. The background server restarts onto the new binary once idle, by the stamp rule under _The Mac's background server_.

**The last step is a launch this app make itself, never `AppHandle::restart`.** `install_update` run off the main thread, where `restart` only ask the event loop to exit and relaunch from inside Tauri's own `RunEvent::Exit` arm — *after* the callback in [lib.rs](../src-tauri/src/lib.rs), which end in `libc::_exit(0)` to dodge ggml-metal's atexit abort. So the relaunch was never reached and Install read as a quit that never come back (DRA-160). Nothing here may call `restart` again while that `_exit` stand.

**Launch first, exit second, and that ordering is the whole of the reporting.** `relaunch` run `open -n <bundle>` — Launch Services, so the new instance is registered, and a refusal come back as a non-zero status carrying a sentence rather than as a process already gone. Only then `app.exit(0)`. A rejected `invoke` is therefore a real answer the UI can draw, where a diverging call left nothing running to say anything at all. `-n` is load-bearing: this app is still up, and without it `open` merely activate it. **Environment survive** — `open(1)` state that an opened app inherit it "just as if you had launched the application directly through its full path" — where `argv` do not, absent `--args`, and nothing here read any. Success only mean Launch Services took the request; an instance that start and then die look identical from here.

**The two failures are tagged, never told apart by their message.** `InstallError` carry `stage`, because the cures are opposite: a swap that did not complete leave nothing to open, so the button beside the sentence is the answer, where a *relaunch* that failed left the new bundle on disk and only opening it finish the job. Telling a reader to quit and reopen for a swap that never landed send them to do nothing. **Not "changed nothing"** — the plugin move the old bundle to a temp backup before unpacking and a final rename that fail return `Err` without putting it back, so the weaker claim is the true one. An unshaped rejection read as `install`, the safe half. The sentence itself is `updateFailure` and both surfaces call it — the sidebar row **and** the Settings row, since Settings cover the sidebar and a reader who pressed the button there would otherwise get no answer at all.

**Except when the user asks.** "Check for Updates…" is a question, so it is answered either way and both answers retire after 4s. The menu item **emit to the frontend** rather than checking in Rust, because the channel lives in frontend local storage; that also mean a manual check reuse the scheduled path and its in-flight guard. The verdict is read off `check_update` resolving with no `update_status` having arrived.

# Changelog

**[CHANGELOG.md](../CHANGELOG.md) is the one source** for the GitHub release notes, drayhq.com/changelog and Settings → Changelog; its format is written at its top. **The one parser lives on the site** ([changelog.ts](../../web/src/lib/changelog.ts)), read at build and served as `/changelog.json`, which the app fetches ([changelog.ts](../src/lib/changelog.ts) holds the types again, the apps sharing no code). Fetched from `www.` — the apex redirects, and a redirect carries no CORS header. Media sits in `apps/web/public/changelog/` and is served by the site, never bundled into the app. Vercel meters those bytes, so heavy video belongs on R2 once there is much of it.

**`notify` raises [WhatsNewCard](../src/components/WhatsNewCard.tsx)** for the newest flagged release the reader already runs and has not seen. No timer, and seen is recorded on Dismiss or View all, not on showing, so quitting brings it back. A fresh install marks everything seen, told apart from an older install meeting the feature by `localStorage` holding no keys at all — and it writes its own version as seen **at module load**, not when the feed lands, since `applyZoom` writes a key every launch and a first launch whose request failed would otherwise read as an old install next time. **Which is why `tauri dev` never shows the card**: the shim picks a new port each launch, so every dev run is a new origin with empty storage and reads as a fresh install. Test it with that check forced off.
