# Git and models

**Git.** [git.rs](../src-tauri/src/git.rs) and [github.rs](../src-tauri/src/github.rs) are the only places the app shells out to anything but `claude`. `checkout_branch` validates the name against branches git just listed — injection is not the risk, but a name starting with `-` parses as a flag. It runs when the user picks a branch, not at send, and `dirty` is re-read at pick time.

**`-w` worktrees do not fork from the checked-out branch.** The CLI resolves the repo's default branch, fetches `origin/<it>` and passes that to `git worktree add --no-track -B`, so the fork point is `origin/main` whatever is checked out, and a failed fetch falls back to local `HEAD`. The `-w` flag surface exposes no base ref, hence the composer hides the branch picker in worktree mode and shows the resolved base.

**Models.** [models/models.rs](../src-tauri/src/models/models.rs) name Claude Code's and Codex's **fallback** lists; the frontend build its picker from `list_models`. **Codex's real list is asked of Codex** ([harness/codex/models.rs](../src-tauri/src/harness/codex/models.rs)), so a model OpenAI ship is pickable with no Dray release — the table behind it is what a missing or broken `codex` leave the picker drawing.

**The ladder is six rung and `ultra` is per *model*, never per family.** Codex report it on Sol and Terra, stop Luna at `max`, and stop the older generation at `xhigh` — so a family-wide list would put a level on the wire the model refuse. **`ultra` is not a louder `max`**: Codex describe `max` as maximum reasoning *depth* and `ultra` as maximum reasoning **with automatic task delegation**, and offer both on one model. Claude Code's own list stop at `max`; its `ultracode` is a **session boolean** pairing xhigh with dynamic-workflow orchestration, set through `--settings` or `apply_flag_settings`, so it is no rung and belong nowhere in [`Effort`] — see DRA-140, which also carry the finding that `apply_flag_settings` take `effortLevel` and so may retire the effort respawn under _Known issues_.

**A rung is a persisted enum, and `ultra` never reach disk as itself.** An older build reading a level it cannot spell fail that line, and the index parse as one `Vec` — so one `ultra` session read as **no sessions at all** in a release build sharing `~/.dray`. Measured, not feared. `encode_effort`/`decode_effort` in [store.rs](../src-tauri/src/store.rs) are the only two places that know: `ultra` go down as **`max`** — a real level that build can run, one rung below — with the truth beside it in `effortAbove`, which its `unknown` flatten carry back untouched. Decode honour that field **only while `effort` is still `max`**, since an older build rewriting the entry write its own level there and leave the forward field standing; reading it then would put the session back on a level the reader just left. Same bargain `Harness::Other` make, same ordering rule — protection ship *before* the value, never after, which is why the stand-in has to be a level already shipped rather than a new spelling of "unknown".

**`effort_above` is a `String` and must stay one.** Typed as `Effort` it recreate the very bug it fix, one build later: the next rung a newer Dray write there fail *this* build's line and take the index down. A string hold a level nobody here has heard of, so `carries_unreadable_level` **carry it through whole** — stand-in kept runnable, forward field handed back untouched, exactly how `unknown` treat a field it never heard of. It is dropped only when the reader move the effort off the stand-in, since that is them asking for the level they moved to.

**Codex's list is the wire's, with Dray's ids kept.** A row Dray already name keep the table's **id and label** — an index entry hold `gpt56_sol` where the wire say `gpt-5.6-sol`, and minting the wire spelling would leave every running Codex session naming a model the picker no longer list, which read as the composer moving it to the default. Only a model this build never heard of is minted from the wire, id and all. Everything else is the row's own: ladder and image support. **Effort default stay Dray's — Medium**, never the row's `defaultReasoningEffort` (Codex say `low` on its top two today): which model exist is Codex's answer, how hard Dray set one working is Dray's, and a CLI setting must not arrive through the back door of a list read for something else. Reader's own pick override it and persist, as before. **Tier is the table's, capped at three** — a row Dray name keep its table tier (6.1 Sol, 6 Astra and 6 Sol in the default shortlist, the rest off), and a model Dray never heard of lead and compete for the top three, so a new flagship land at the top of the chord the day it ship. A Codex not yet updated to list 6.1 Sol draw the rows it does list up there rather than promote 6 Luna into the gap, and default to 6 Astra, the table's next top-level row. **A model named after Dray already discovered it keep the wire id** (`gpt-6-sol` and `gpt-6.1-sol`, not `gpt6_sol`) — a reader on the newer Codex already had sessions minted under it. Hidden rows (`gpt-reserve`, `codex-auto-review`) are asked for and dropped. The probe is a throwaway app-server ([probe.rs](../src-tauri/src/harness/codex/probe.rs), shared with the skill picker), cached for the life of the process, and an answer this build cannot read fall back to the table rather than to an empty picker. **`nextCursor` is followed**, capped at ten pages — the server take `limit` and refuse a bogus cursor outright, so paging is real and a first page read as the whole list would drop models silently. **A model neither list name is taken as written** — pi's rule, pi's reason: a *discovered* model is one no table here hold, so a restart whose probe fail would otherwise leave a live session's own model unnameable and report "not a Codex model" about a model Dray itself offered. The id **is** the alias, the stand-in carry no ladder (so that spawn omit `--effort`), and a Codex that cannot run it say so in its own words. It must not make everything runnable, so another harness's alias still answer `None` — `find_model` is what ask that, holding both harnesses. Cost, stated: `runs_on` cannot judge a model newer than the build, so `send_msg` ask "did the lookup find it" for Codex instead, and `dray new` read its **alias and its default off the same list** — a model named here that the installed Codex do not list is a create failing at the spawn for a choice nobody made.

**The frontend hold one model list per harness, never one list plus a note saying whose it is** (`modelsByHarness` in [useSessions.ts](../src/hooks/useSessions.ts)). A single list carry the *previous* harness's answer until the next land, which draw Claude's models under pi's mark for the second pi's read spawn a child for; blanking it instead only move the flaw, since every switch then empty the menu for the frame an `invoke` take and the two table-backed harnesses start flickering too. Keyed, a harness already visited answer on the same frame the toggle move — and `setHarness` repair the pick against that entry in the **same commit**, so the trigger never name a model one frame before the fetch correct it. Only a first visit to a harness whose list is a genuine read draw the waiting row, which there is the truth rather than a stutter.

**The fx list on screen follows the pick, never fx's global provider alone** (`fxListFor` in [model.ts](../src/lib/model.ts)). `modelsByHarness.fx` holds what the global provider last answered; what is drawn is the cached list of the provider serving `modelId`, falling to that slot only where no cached list names it. The provider is one setting for the whole machine, so drawn from the slot alone a switch in session A put A's new provider under every other fx session's picker — its thumb, its rows, ⇧⇥'s cycle — and a list landing after the reader had moved on repaired B's model onto A's provider's pick (DRA-254). Hence the landing repair keeps any pick the cache can name a provider for, and a seed with nothing cached still moves the pick off the old provider, or the derived list would keep following it and the switch would read as inert.

**fx's pick is repaired per provider at every seed, and `handleNewSession` is a seed.** `repairFxModel` — `usableFxModel` over the reader's last model per provider (`ade.fxModelPick`) — is what every fx site must use, never `usableModel`, whose fallback for fx is the unset sentinel. The two disagree in the ordinary state after a provider switch: the reload repairs the on-screen pick through the raw setter, so `prefs.modelByHarness.fx` keeps naming the model of the provider *left*, and a seed judging that against the list on screen throws it away. From another fx session the harness has not changed, so no fetch follows to put it back, and the trigger says "Select Model" over a pick the reader made an hour ago.

**Shift+Tab cycle exactly what the picker draw, and that is one function** — `shortlist` in [starredModels.ts](../src/lib/starredModels.ts), read by both. A chord landing on a model the menu never offered is the bug sharing prevent, and pi had it: the menu drew the reader's shortlist while the chord walked every model every logged-in provider serve. `cycledModels` is the same answer for `App`, reading the stars through `readLocalStorage` **at the press** rather than holding them — a second `useLocalStorage` copy there would drift from the picker's the first time the library dialog wrote one.

**Every harness draw the reader's own shortlist, chosen under "Shortlist models", and there is no "More models" submenu.** A shortlist start empty, so the first list to land for a harness (per provider on fx) seed it once, marked in `ade.fxStarsSeeded` under `seedKey` — `harness:<name>` for the written lists, since fx has providers named `codex` and `grok`. Claude Code, Codex and grok seed every row not marked **`secondary`**, so Claude Code start on two (Fable 5.1, Opus 5.5); fx seed its own table; pi seed nothing. `secondary` is read at seeding and nowhere else: it decide what is on **by default**, never what may be run. **Seeding once was right for the reader's choices and wrong for the vendor's**: Codex 0.164 shipped GPT-6.1 Sol as its default and no seeded shortlist ever drew it. So `ade.offeredModels` records every row each seed key has shown, and `starsToAdd` ([starredModels.ts](../src/lib/starredModels.ts)) stars a non-`secondary` row the first time it is offered and never again — unstarring sticks. A key seeded before the record existed has no history, so that one landing stars the harness's default alone. The session's current model is always drawn, starred or not.

**Top-level ids are bare aliases (`opus`) so sessions follow the latest model; a pinned id (`claude-fable-5`) live under `secondary` only.** An alias follow the latest — `fable` resolve to `claude-fable-5-1` today, per the CLI's own alias table — which is what the top level want and exactly what somebody pinning a previous generation ask *not* to happen.

**Claude Code's real list is asked of Claude Code too** ([harness/claude_code/models.rs](../src-tauri/src/harness/claude_code/models.rs), #674). Since v2.1.310 the `initialize` reply carry `models`: the bare aliases plus every pinned generation the CLI still serve (13 rows, Opus 4.6 up), each with its own `supportedEffortLevels`, `supportsFastMode` and optional `disabled`. So a ladder or a fast switch is per row off the wire, and a previous generation is pickable with no table row. `default` is dropped (Dray picks its own default) and a disabled row is dropped. **The first read wait for it, up to 4s, and nothing after does**: the picker repair the pick against whatever list land first, so answering the table at once moved a remembered `claude-opus-4-6` onto `opus` before the real list could name it. A probe landing past the wait still emit `models_changed` — fx's bargain. A row the table name keep the table's place and shortlist tier, so a fresh install still seed Fable and Opus; an unknown bare alias lead, an unknown pinned id sit under "Shortlist models". **The list live in memory, so a restart forget it**: `find` answer the wire list, then the table, then any `claude-*` id **as written** with no ladder — Codex's stand-in rule — and `runs_on`, `find_model` and `id_for_arg` all go through it, so a saved session on a pinned id resume before the probe land. The refusal fallback read `known()` instead, since a model it record must be one the picker can draw.
