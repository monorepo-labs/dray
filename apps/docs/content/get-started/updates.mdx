Dray checks for a new version when it starts and every six hours after that. When it finds one, it downloads it in the background. You choose when to restart onto it.

## Install an update

When an update has downloaded, the bottom of the sidebar shows **Restart to update** with the new version number. Click it. Dray installs the update and opens again.

With the sidebar folded to its icon rail, the row is a restart icon at the bottom of the rail; hover it for "Restart to update to v…". The download's progress and the answer to a check show there as icons too, with the words in their tooltips. See [the sidebar](/using-dray/sessions#the-sidebar).

While any session is mid-turn, the button waits. It is dimmed, and hovering it says "Waiting for the running turn to finish." Restarting would cut those turns off, so it is not offered until they end.

On Linux, a `.deb` install asks for your password once, the same prompt the system's own updater shows. An AppImage replaces its own file and asks nothing.

Sessions survive the restart. The background process that runs them moves onto the new version on its own, once no turn is running.

If the install fails, the sidebar says "Couldn't install the update." If the update installed but Dray could not reopen itself, it says "Update installed. Quit and open Dray again."

## Check for updates by hand

Two places do the same thing:

- On a Mac, the menu bar: **Dray → Check for Updates…**. The answer shows at the bottom of the sidebar.
- Settings → About → **Updates**, with the **Check for updates** button.

The answer shows for a few seconds: "Up to date", the download's progress, or "Couldn't check for updates" ("Couldn't check" on the Settings button). If a new version is ready, Settings shows **Restart to update** on the same button.

## Stable and beta

There are two channels. Stable is the default. Beta gets new versions early, before they are fully tested.

To switch, open Settings → About → **Beta updates**, click **Turn on** (or **Turn off**), then **Confirm**. Dray checks the new channel straight away.

- On beta you still get every stable release, since a stable release is newer than the betas before it.
- Leaving beta does not move you back to an older version. You stay on the beta you have until a stable release passes it.

## What's new

After an update, Dray shows you what is new, once, the next time it opens. There are two sizes.

**A full-window page**, for a release with big new features. It covers the whole window: a heading like "3 new things in Dray.", then a card per feature with its title and a picture or video. A card can carry a link that takes you there, such as to a new task or a Settings tab. **Continue** or `Escape` closes the page. If you skipped a few versions, the page holds the big features from each of them.

**A small card**, for a release with smaller changes worth a look. **What's new in Dray** with the version appears in the bottom-left corner, listing the first few changes. Click **View all** for the full changelog, or **Dismiss**. With the sidebar folded to its icon rail, the card is a sparkle button at the bottom of the rail and opens beside it.

Either one comes back each launch until you close it. Dray only shows what is in the version you are running.

The full changelog is in Settings → **Changelog**, newest first. Settings → About → **What's new** → **View changelog** goes there too. On the beta channel the list includes beta releases. The same list is at [drayhq.com/changelog](https://www.drayhq.com/changelog).

## The `dray` CLI updates with the app

The [`dray` command line](/cli) ships inside the app, on a Mac and on Linux. Each time Dray starts, it puts its copy in `~/.local/bin` if the one there differs, so the CLI always matches the app. There is nothing to update by hand: on a machine with the app, `dray update` only says "The Dray app keeps this CLI up to date. Update the app to update it."

A server you added updates on its own channel. See [Connect a server](/server).

## Your agents

Each agent CLI has its own version, apart from Dray's. When an agent you use has a newer version out, the new-task composer shows a line under it, like "Codex update available", with an **Update** button. That runs the agent's own updater.

For pi, fx and OpenCode, the update waits while one of their sessions is mid-turn. If an update fails, the line shows why and offers **Run in Terminal**.

## Limits

- The app does not restart itself onto an update. You click **Restart to update** when it suits you.
- If you check for updates from the menu while the sidebar is hidden, the answer is drawn nowhere. Use Settings → About instead.
